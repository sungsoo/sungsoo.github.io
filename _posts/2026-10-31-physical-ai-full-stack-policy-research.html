PART 01 · DEFINITION

정의 — 풀스택은 물리적 결과에 책임지는 연결 범위

[해석·작업 정의] 피지컬 AI(Physical AI)는 신체를 가진 시스템이 실제 환경을 관측하고 행동의 결과를 다시 관측하면서 임무를 수행·학습하는 지능이다. 풀스택(Full Stack)은 그 지능의 모델뿐 아니라 신체·데이터·상태 추정·예측·계획·제어·컴퓨팅·검증·운영을 연결한 분석 범위다. 최신 서베이는 물리 상호작용의 폐루프를 중심으로 모델·학습·제어·컴퓨팅·평가를 다루지만, 여기서 쓰는 9계층 분류 자체가 공인 표준은 아니다. 문헌의 분류를 연구기획에 맞게 재구성했다. [R1]↗

동일한 로봇이 언어를 이해하고 미래 영상을 생성해도, 부품을 잘못 집거나 접촉력을 제어하지 못하면 임무를 달성하지 못한다. 따라서 “무엇을 예측하는가”와 “어떤 물리 결과를 만들 수 있는가”를 나누어 정의해야 한다. 모델이 교체되어도 관측·행동의 의미와 검증 조건이 유지되는가가 풀스택의 실질적인 경계다.

PART 02 · PROBLEM DEFINITION

문제 정의 — 불완전한 정보로 제약을 지키며 임무를 끝내기

[해석] 문제는 자연어 지시를 행동 벡터로 바꾸는 데서 끝나지 않는다. 실제 상태를 모두 알 수 없고, 마찰·질량·신체 특성이 달라지며, 센서와 계산은 지연된다. 그 조건에서 목표 상태를 만들고 안전·시간·에너지 제약을 유지해야 한다. 물체가 가려졌을 때 잡힌 상태를 추정하고, 들어 올린 뒤 미끄러짐을 확인해 힘을 바꾸는 과정이 대표적이다.

평가 단위도 명시해야 한다. 하나의 pick-and-place 성공, 여러 하위과제의 완료, 교대 시간 동안의 운용은 서로 다른 주장이다. 연구기획서에는 목표물·허용 오차·제한 시간·허용 개입·중단 조건·재시도 비용을 포함하는 임무 명세를 먼저 둔다. “사람 수준”이라는 표현도 동일 장비·대상·품질·시간 조건의 사람 기준선 없이 수치 목표로 바꿀 수 없다.

부분관측 의사결정 과정(Partially Observable Markov Decision Process, POMDP)을 출발점으로 다음과 같이 형식화할 수 있다. 아래는 특정 논문의 재현 수식이 아닌 문제 설명을 위한 일반화다.

st+1∼P(·|st,at,e),ot∼O(·|st),at∼πθ(·|bt,g)

st는 물체·로봇·접촉의 실제 상태, ot는 센서 관측, at는 행동, e는 신체·환경 조건, g는 임무 목표다. 믿음 상태(belief state) bt는 관측·행동 이력으로 추정한 상태 분포다. 상태와 신체 기술이 충분하고 전이·관측의 확률 표현이 유효하다는 가정 아래 쓰는 모델이며, 실제 접촉의 비정상성까지 자동 해결하지 않는다.

개별 성능이 전체 성공으로 이어지지 않는 이유. 상태 추정의 좌표 오차는 계획의 목표점을 바꾸고, 계획 지연은 오래된 관측에 따른 행동을 만들며, 제어 실패는 이후 데이터를 바꾼다. 단계별 성공 확률을 곱하는 단순 근사는 각 단계의 조건부 실패가 정의될 때만 유용하다. 실제 오류는 상관되므로 독립을 가정해 시스템 신뢰도를 계산해서는 안 된다. 같은 장면에서 목표 지시만 바꿨을 때 행동이 충분히 달라지지 않는 grounding gap 연구는 명목 성공률만의 한계를 보여준다. [R12]↗

핵심 개념 — 상태, 시간, 행동의 의미를 맞추기

[해석] 표현(representation)은 모델이 쓰는 정보 형식이고, 상태(state)는 임무 판단에 필요한 세계·신체의 변수다. 좋은 표현은 단순히 압축률이 높은 표현이 아니라, 접촉 안정성·목표 달성·위험 판단에 필요한 변수를 유지한다. 예측(prediction)은 가능한 결과를 추정하고, 계획(planning)은 목표와 제약 아래 행동을 선택한다. 예측 영상의 선명도는 계획의 물리적 타당도와 다른 지표다.

정책(policy)은 상태·목표에서 행동을 고르는 규칙이며, 제어(control)는 피드백을 이용해 그 행동을 실제 신체에서 구현한다. 하나의 신경망이 두 역할을 함께 학습할 수 있지만 측정 책임은 분리하는 편이 낫다. 일반화(generalization)는 고정된 모델이 새로운 조건에서 수행하는 능력이고, 적응(adaptation)은 새 데이터나 상호작용으로 바뀌는 과정이다. zero-shot 결과에는 현장별 학습 데이터가 없었는지, 추가 보정·프롬프트·시연이 있었는지도 기록한다.

동기와 배경 — 데이터와 물리 제약이 모델 밖에 남는다

[해석] 웹 영상은 다양한 상황을 보여주지만 힘·마찰·구동 명령과 실패 원인을 충분히 기록하지 않는다. 반대로 로봇 시연은 행동과 결과가 가깝지만 수집 장치·시간·사람 비용이 든다. 공동학습과 합성 데이터는 이 간극을 줄이는 방법이지만, 현장의 접촉·신체 차이를 없애는 증거는 아니다. π0.5와 GR00T N1은 이질적 데이터의 활용 가능성을 보여주는 근거로 읽어야 한다. [R4]↗ [R3]↗

현장 다양성은 외관 변화에 그치지 않는다. 투명 부품은 관측을, 마찰 변화는 접촉을, 다른 손은 행동 공간을, 불안정한 네트워크는 관측 시점을 바꾼다. 한 축에서 성능을 보존해도 여러 축이 동시에 바뀌면 실패할 수 있다. 데이터 설계에는 성공 행동뿐 아니라 중단·개입·재시도와 당시 상태를 포함해야 한다.

Robot Data Factory는 원시 기록량보다 임무와 물리적 결과가 연결된 경험의 생산·검증을 강조한다. 구현된 운영 코어와 향후 데이터·코드 공개, 통제된 학습 개선 검증은 구분되어 있다. 따라서 데이터 팩토리를 구축했다는 사실을 곧바로 일반 로봇 능력 향상으로 치환해서는 안 된다. [R8]↗

[해석] 계층 내부의 난제는 센서 잡음, 부분관측, 다중 미래, 접촉 제어, 모델 계산량 등이다. 계층 간 난제는 다른 시간·좌표·행동 의미·불확실성을 가진 모듈이 상대의 가정을 깨뜨리는 것이다. 예를 들어 비전 모델의 높은 물체 검출률은 잘못된 카메라 외부 파라미터 때문에 삽입 실패로 이어질 수 있고, 정확한 계획도 명령 적용 시점이 늦으면 무효가 된다.

DepthWorld는 RGB 영상만으로는 다중 시점의 일관된 3차원 세계가 확보되지 않는다는 문제에 깊이 감독을 결합한다. 그 기여를 평가할 때는 기하 정확도와 downstream 접촉 성과를 별도 측정해야 한다. [R13]↗ RTC는 계산과 실행을 겹치지만 새로운 접촉 사건을 얼마나 빨리 반영하는지까지 장비에서 확인해야 한다. [R5]↗

또 하나의 난제는 동일 근거를 학습과 검증이 공유하는 데서 발생한다. 같은 월드모델이 행동 후보를 만들고 그 행동을 채점하면 오류가 상쇄되거나 서로 강화될 수 있다. 독립 센서·실물 hold-out·다른 평가기로 검증 경로를 분리할 필요가 있다. 이는 특정 논문이 이미 해결한 결과가 아닌 시스템 연구 과제다.

[해석] 구조화 추론은 잘못된 primitive를 선택하면 장기 오류를 만들고, tactile RGB는 센서 외관·마찰·조명 변화에 취약할 수 있다. 가치모델은 결과 점수가 높아도 복구 가능성을 오판할 수 있으며, fleet 경험은 한 기종의 편향을 다른 기종에 확산시킬 수 있다. 표현·행동·가치·버전이 같은 상태 전환과 실패 의미를 공유하는지를 계층 간 시험으로 다뤄야 한다.

비동기 연결이 만드는 추가 실패

  • stale semantic context: 빠른 촉각 수정이 오래된 시각 메모리에 조건화되어 잘못된 residual을 만들 수 있음
  • memory–action mismatch: 장기 기억이 과제를 잘 요약해도 현재 기종이 실행할 수 없는 subtask를 반환할 수 있음
  • uncertainty shortcut: 불확실성 점수가 과제 간 coverage 차이는 잡지만 동일 과제 내 실패 순위를 못 잡을 수 있음. R42가 지적한 평가 사각지대 [R42]↗
  • stage credit leakage: 실패한 하위과제의 TD 오차가 이전·다음 단계에 잘못 전파되어 이미 습득한 능력을 훼손할 수 있음 [R44]↗
  • sensor realism collapse: 합성 깊이 잡음이 실제 invalidation과 measurement inaccuracy를 섞으면 sim-to-real 성공이 무너질 수 있음 [R45]↗

  3. Uncertainty gate: single-policy post-hoc head가 held-out 카메라·지시·상태 조합에서 잘못된 자동실행을 줄이면서 불필요한 개입 증가를 제한하는가? AUROC뿐 아니라 위험가중 selective success·개입당 회수 가치·지연을 측정.
  4. Stage-isolated update: 원자 하위과제 기반 RL이 새 병목은 개선하면서 이미 통과한 단계의 회귀와 sim-to-real 비용을 줄이는가? 동일 rollout budget과 paired checkpoint에서 비교.

[논문 보고] ACTS는 사람과 로봇의 공통 행동표현을 ‘센서 운동 + 힘 변화’로 두고 접촉 동역학의 전이를 시험했지만, 시각 외관은 작업마다 다르게 전이되었다. [R22]↗ ContactBench 1.0은 같은 접촉 기술을 여러 연구실이 반복 시험할 수 있도록 제작 자산·시뮬레이션·저항 변형을 묶었고, 평가된 시각촉각 정책이 여섯 과제에서 의미 있는 개선을 보이지 않았다고 보고했다. [R23]↗

[논문 보고] VQ-WM은 first-passage-time 기반 준거리로 제어기가 실제 도달할 수 있는 latent 전이를 찾고, 장기 이산 탐색을 연속 피드백 제어로 닫는다. [R24]↗ PaceVLA는 coarse·fine 행동 디코더와 context router로 구간별 시간 해상도를 바꾼다. [R25]↗

[해석] 네 결과를 한 시스템으로 결합했다는 증거는 없다. 다만 공통 연구 질문은 선명하다. 어떤 접촉 상태를 공유하고, 어떤 장기 전이를 계획하며, 어느 구간에서 시간 해상도를 낮출지를 실행 계약으로 표현해야 한다. [제안] 상태 계약에는 접촉 phase·힘 변화·불확실성, 계획 계약에는 도달가능성·중단 조건, 실행 계약에는 선택한 시간 모드·마감시간·안전 필터 결과를 기록한다. ContactBench류의 공통 과제와 현장 과제를 함께 사용해 모듈별 개선과 전체 임무 순편익을 분리 평가한다.

결합 제안: 상태–행동–가치–버전 계약

[연구 제안] R26–R29를 하나의 시스템으로 직결했다는 문헌 증거는 없다. 제안 인터페이스는 {state, uncertainty, physical primitive, action mode, expected progress, safety envelope, model/data version}을 교환한다. 한 요소씩 고정·교란하고 새 기종·현장·작업에서 성공률, 안전 위반, 사람 개입, 복구시간, 지연·전력, 성공 임무당 비용이 함께 개선되는지를 최소 반증 실험으로 삼는다.

8.9 [제안] State–Stage–Commit–Version 계약

선정 근거를 하나의 시스템으로 결합하면 다음 네 경계가 필요하다. 이는 개별 논문이 통합 성능을 입증했다는 뜻이 아닌 연구 제안이다.

  1. State contract: RGB·촉각·고유감각·과제 상태의 시간 정렬, 결측, 불확실성, 좌표계를 명시.
  2. Stage contract: 현재 하위목표, 완료 증거, 허용 행동, 복구 지점을 버전 가능한 상태로 기록.
  3. Commit contract: 관측 시각, 후보 생성 시각, 실행 예정 시각, pre-commit 검증 결과, 취소·재계획 규칙을 함께 전달.
  4. Version contract: 모델·센서·환경·안전 규칙 변경을 paired rollout과 단계별 회귀 시험에 연결.

통합 실험은 동일한 30–60분 장기 임무 로그에서 ‘빠른 국소 성공’과 ‘임무 전체의 안전·개입·복구·비용’을 동시에 측정해야 한다. 모델 출력보다 commit 기록과 실패 단계가 재현 가능한 검증 단위가 된다.

8.10 비동기 감각·기억·학습을 묶는 Rate–Memory–Uncertainty 계약 [제안]

T-WLA의 빠른 촉각 편집, PAL의 executable subtask list, R42의 uncertainty head, AtomicRL의 하위과제 경계는 서로 다른 시스템을 다룬다. 이를 결합한 시스템이 문헌에 입증된 것은 아니다. 결합 시 각 packet에 timestamp·validity horizon·memory provenance·current stage·embodiment capability·uncertainty·abort condition을 함께 보존하고, 빠른 루프는 이미 승인된 안전 envelope 안에서만 행동을 수정하도록 시험한다.

execute(at)⇔(age(st)≤τstage)∧(ut≤umax)∧capable(mt,embodiment)

여기서 age(st)는 상태의 나이, τstage는 단계별 허용 stale 시간, ut는 불확실성, mt는 기억에서 선택된 subtask다. 이 식은 공식 정책이나 특정 논문의 수식이 아니라 실행 게이트를 명시하기 위한 연구 제안이다.

증거 기반 실행의 결합 구조 [분석·제안]

센서·정책·감시·권한을 다음 인터페이스로 분리한다. state evidence는 관측·접촉·4D 기하와 신선도, status evidence는 진행·성공·실패와 calibration, authority state는 현재 executor와 전환 사유, handoff memory는 목표·단계·최근 행동·위험을 보존한다. OpenTac과 UniFlowWAM은 state evidence의 폭을, P²와 Echo는 status evidence를, TEAR·CARE는 authority state와 handoff를, FastHarness는 review budget을 보강한다. 문헌에 이 전체 조합이 하나의 시스템으로 입증됐다는 근거는 없으므로 통합은 연구 제안이다.

제안 결합 구조: Continuous Mission Assurance Case

[신규 연구 제안] 각 임무 요구를 주장(claim)으로, 센서 교정·상태 추정·월드모델·정책·제어·운영 로그를 증거(evidence)로, 지연·분포 변화·통신 단절·버전 변경을 반증자(defeater)로 표현한다. 각 증거에는 적용 기종·환경·작업·소프트웨어 버전·유효기간·재시험 트리거를 붙인다. 변경이 생기면 dependency graph를 따라 필요한 시험만 실행하고, 중대한 반증자가 열리면 권한 축소·safe stop·rollback을 수행한다. 이는 선정 문헌 전체를 하나의 시스템으로 결합해 검증했다는 보고가 아니라, 그 사이의 책임 공백을 시험 가능한 인터페이스로 만든 제안이다.

누가 행동했는지뿐 아니라 왜 권한이 넘어갔고 어떤 상태가 인계됐는지가 남아야 한다. router가 성공률을 높여도 과도한 사람 호출, cloud 비용, 개인정보 유출, 전환 진동, 오래된 handoff memory가 생길 수 있다. monitor·router·executor를 각각 업데이트하면 결합 회귀가 나타날 수 있으므로 버전별 replay와 실물 hold-out이 필요하다.

신규 미해결 문제: 성공 데이터가 실패를 지우는 역설

  • 라벨 순환성: 자동 outcome label로 학습한 감시기가 같은 labeler의 판단을 재현할 수 있어 독립성이 약해짐.
  • 복구의 비가역성: 되감기 가능한 관절 경로와 되돌릴 수 없는 접촉·파손·사람 반응을 구분하는 formal precondition 부재.
  • 세계 프로그램의 false-safe: 기하·trajectory replay가 맞아도 마찰·유연체·센서 invalidation이 틀리면 안전한 것처럼 보일 수 있음.
  • 시간척도 혼동: <400 ms teleoperation, flow sampling latency, 저수준 servo 주기를 같은 ‘실시간’ 수치로 비교할 수 없음.
  • 복구 후 데이터 편향: 성공한 retry만 남기면 원래 실패와 사람 개입 비용이 사라져 다음 모델이 취약성을 학습하지 못함.

따라서 dataset card만 아니라 recovery card와 executable-world validation report가 필요하다는 것이 본 분석의 제안이다.

실패 충실성과 안전한 성공의 사각지대

  • False-safe world: outcome은 맞지만 실패 이유·단계·경계를 틀리게 재현해 잘못된 배포 승인을 내리는 문제.
  • Unsafe success: 과제는 끝났지만 충돌 여유·힘·속도·절차 안전을 위반한 실행이 성공률에 포함되는 문제.
  • Recovery loop trap: completion checker와 atomic skill이 같은 편향을 공유해 실패–복구–재실패를 반복하는 문제.
  • Authority split brain: 다중 로봇 leader handoff 뒤 서로 다른 mission state·계약 버전을 보유하는 문제.
  • Acceleration regression: cache reuse·pruning·one-step diffusion이 평균 성공을 보존해도 tail action error·deadline jitter를 키우는 문제.
  • Contract drift: 모듈 업데이트 뒤 neighbour assumption이 바뀌었지만 계약 quotient·fault suite가 갱신되지 않는 문제.

[새로 드러난 사각지대] (i) policy shift를 감지해도 conditional mechanism 자체가 변했는지 구분하기 어렵고, (ii) VLM 내부에 원인 정보가 있어도 답변·행동으로 읽히지 않을 수 있으며, (iii) residual correction은 기존 정책의 실패 구간을 고치면서 다른 구간의 안전을 훼손할 수 있고, (iv) seed-agent 시험은 현실의 통신·기구·사람 행태를 모두 포괄하지 못한다. 장기 운용에서는 certificate expiry, active sensing 비용, repair-induced distribution shift, partner churn을 별도 failure mode로 등록해야 한다.

[정책이 드러낸 미해결 문제] 데이터 자산화는 권리·비식별화·반출·모델 삭제 요구와 충돌할 수 있고, 현물 인정은 데이터 품질과 downstream 기여를 어떻게 평가할지 새 기준을 요구한다. 보급 대수는 늘어도 장기 무인 운용, 업데이트 회귀, 사고 책임, 공급자 교체 가능성이 미해결이면 운영 부채가 함께 커질 수 있다.

[신규 미해결 문제] 첫째, gating distribution shift: 어떤 과제에 상상이 유익한지 학습한 gate가 새 공정·정밀도·장애물에서 거꾸로 판단할 수 있다. 둘째, evidence debt: RoboSeed가 드러내듯 serving trace와 재현 근거가 빠진 모델은 성공률이 높아도 선택 불가능하다. 셋째, assurance composition: 기호 계약, neural perception, feasibility oracle, 사람 개입의 오류 확률을 하나의 인증 주장으로 합성하는 방법이 부족하다. 넷째, embodiment drift: glove·tool adapter·센서가 마모되면 초기 캘리브레이션과 contact wrench 의미가 변한다. 다섯째, recovery regression: 국소 복구가 현재 하위과제는 살리지만 이후 품질·안전에 숨은 부채를 남길 수 있다.

해결 여부는 단발 성공률이 아니라 gate regret, missed evidence, false assurance, calibration drift, downstream condition violation을 교대·주·버전 단위로 추적해 판단해야 한다. 업데이트 후 평균 성능이 유지돼도 희귀 정밀 작업·위험 공정의 tail failure가 늘면 배포를 승인할 수 없다.

향후 방향 — 데이터에서 운용 증거까지 단계별로 축적

[제안] 전망의 기준일은 2026년 10월 31일이다. 아래에서는 사용자의 연구기획 범위인 2028–2032년 안에서 단기 2028–2029년, 중기 2030–2031년, 장기 2032년을 정의한다. 일반적인 장기 기술 예측이나 공식 정책의 전체 기간을 재정의한 것이 아니다. 각 단계의 진입은 달력만이 아니라 전 단계의 검증 결과에 달려 있다.

모델 성능 향상은 통합 후보를 제공하고, 시스템 통합은 오류를 드러내며, 실물 검증은 그 조합의 유효 범위를 정한다. 운영 확산은 검증된 범위를 새로운 현장으로 넓히는 일이다. 하나의 단계도 다음 단계를 자동 승인하지 않는다. 각 단계에서 부적합한 가설을 중단·수정할 수 있도록 개발 평가와 독립 평가를 분리한다.

범용성을 사업의 처음부터 모든 현장·기종을 다루는 것으로 설정하면 검증 조건이 사라진다. 초기 임무를 좁게 정의하되 데이터·상태·행동·평가 계약을 재사용 가능하게 설계하고, 다음 현장을 추가하는 한계 비용을 줄이는 것이 더 검증 가능한 방향이다.

[제안이며 공식 일정 아님] 2028년에는 실물–simulation paired failure corpus와 reason/stage/boundary taxonomy를 구축하고 기준선을 측정한다. 2029년에는 state·compute·recovery contract와 EAST형 valid fault operator를 공통 인터페이스로 시험한다. 2030년에는 제조·물류·서비스·자율실험의 제한 현장에서 edge budget과 recovery/authority handoff를 통합한다. 2031년에는 복수 기종·현장 update에 contract-generated selective regression을 적용한다. 2032년에는 독립기관이 unsafe success, missed critical regression, recovery-induced harm, qualified mission당 비용을 공개 프로토콜로 검증한다.

각 단계의 진입 조건은 이전 단계의 평균 성공률이 아니라 failure fidelity calibration, deadline/safety 비열등성, contract conformance, replay 가능성이다. 목표값은 2028년 복수 현장 기준선과 위해 심각도 분석 후 설정하며 정책 목표로 추정하지 않는다.

[우선순위 조정] 단기 2028년에는 변화 manifest·policy-conditioned coverage·원인 식별성 기준선을 먼저 만든다. 중기 2029–2030년에는 rollback/correction을 실물 비용·2차 위해와 결합하고, 다기관 seed compatibility 시험을 운영한다. 장기 2031–2032년에는 certificate expiry와 선택적 재검증을 현장 운영에 연결한다. 이 연도는 공식 정책 일정이 아니라 제안 연구기획 범위다. 선행 조건은 공통 trace schema, 개입 taxonomy, 독립 hold-out 현장, safe-stop authority이며, 산출물은 모델 자체보다 재현 가능한 intervention pack·certificate·regression evidence다.

[일정 해석] P13의 2030 보급 목표는 공식 정책 일정이고, 본 글의 2028–2032 연구기획은 분석자 시나리오다. 2028–2029년 기준선·계약·장비 관문, 2030–2031년 공정·복수 현장 전이, 2032년 공장 장기 운용·독립 회귀 증거의 순서는 제안이며 확정 정부 일정으로 표현하지 않는다.

[10월 31일 우선순위 정밀화] 단기 2028–2029에는 대형 모델 사전학습보다 임무 slice–계산 경로–증거 schema를 먼저 고정한다. 같은 정책의 fast/imagined path와 실물 paired trial을 확보하고, 촉각·도구·기종·주파수 metadata를 표준화한다. 중기 2030–2031에는 task graph·runtime assurance·국소 복구와 장비–공정 전이시험을 결합한다. 장기 2032에는 공장 여러 공급자 업데이트에서 certificate expiry와 evidence debt를 자동 탐지한다. 단계는 전망이며 공식 일정이 아니다. 이전 단계에서 gate regret·false repair·누락 근거가 허용범위를 넘으면 다음 단계로 넘어가지 않는다.

[정책 명시·요약] 피지컬 AI 미션은 사람과 협력하는 행동·조작 능력, 풀스택 경쟁력과 산업 생태계, 현장 학습과 활용 확산을 연결한다. 인쇄 p.48은 2029년에 모델·물리적 세계 예측·데이터의 기반과 제한된 작업 적용을, 2032년에 긴 작업·시뮬레이션 순환·빠른 제어 통합과 국민 체감 성과의 확대를 제시한다. 이 글은 정책의 “인간 수준”이나 “국민 체감”을 이미 달성한 상태로 서술하지 않는다. [P1]↗

[신규 정책이 요구하는 변화] P13의 보급 목표는 수단과 규모를 제시한다. 최종 성과는 단순 도입 여부가 아니라 중소 제조현장의 노동력·숙련 전승·위험 공정·생산성 문제에 생긴 변화로 검증해야 한다. 공식 목표값을 연구 성능 목표로 복사하지 않고, 2028년 현장 기준선에서 품질적합 무개입 완료·위험 노출당 위반·사람 구조시간·성공 임무당 비용을 측정한 뒤 기술 목표값을 정한다.

13.4 기술적 공백: 구성요소의 존재와 임무 충족 구분

현재 연구로 일부 충족: 다중 데이터 기반 행동 학습, 일부 신체 전이, 비동기 실행, 촉각 기반 실물 조작, 생성 시뮬레이션의 정책 비교 등은 구현 가능성을 뒷받침한다. 추가 연구 필요: 이를 동일한 상태·행동 계약으로 통합하고 복합 변화·장기 복구·갱신 회귀를 시험하는 일이다. 근거 부족: 선정 문헌만으로 국내 전반의 인간 수준 성능, 전 현장의 경제성, 무인 장기 운용과 포괄적 안전 보장을 판단하기 어렵다.

성공한 기술을 도입하는 것과 국가가 책임질 공통 기반을 확보하는 것도 다르다. 국내 데이터 접근·수정·감사·이전 가능성, 모델 교체권, 장비 adapter와 검증 도구의 재사용성을 산출물로 정의해야 한다. 이것이 “국산”이라는 표기보다 실질적인 자립 역량을 측정하는 방법이라는 것이 본 글의 해석이다.

[충족·공백 구분] P13으로 확정된 것은 확산 방향·정책 목표·지원축이다. 장비–공정–공장별 안전 수용 기준, 사람 개입 상한, 실패 복구 증거, 현장/기종 전이 비용, tail latency·전력, 공급자 교체·업데이트 회귀는 추가 연구가 필요하다. 107편의 연구는 후보 방법을 제공하지만 국내 중소 제조현장 전체의 경제성과 안전을 입증하지 않는다.

13.5 출연연의 역할: 공통 기반·통합·독립 검증

[제안] ETRI는 정보통신·AI·연산·네트워크 기술을 연결하는 공통 인터페이스, 멀티모달 상태·행동 모듈, 엣지 실행, 데이터와 평가 도구를 맡는 역할을 검토할 수 있다. 이는 기관에 이미 배정된 공식 임무라고 확인한 내용이 아니라 역할 설계안이다. 모든 로봇 하드웨어·현장 운영·인증을 단독 수행하는 구상은 피한다.

대학은 접촉 표현·학습·계획의 새 가설과 분석, 기업은 장비·제품·현장 프로세스·운영비, 타 출연연은 신체·물성·제조·시험 기반을 책임지는 협력을 설계할 수 있다. 수요기관은 실제 임무와 수용 기준을 정의해야 한다. 개발 조직의 성과 평가와 독립 검증의 승인 권한을 나누고, 사업 시작 시 데이터 권리·공유 범위·위험 중단 책임을 합의한다.

[출연연 역할 보강·제안] ETRI는 P13이 요구한 데이터–AI–로봇 연계를 위해 제조 장치 adapter, 시간·좌표·권리·버전 schema, 엣지 실행, 공통 regression pack, 현장 증거 원장을 제공하는 통합·검증 허브를 맡을 수 있다. 이는 P13이 ETRI에 직접 배정한 공식 역할이 아니다. 대학은 새 원리와 공개 benchmark, 기업은 장치·공정·품질·운영비, 타 출연연은 소재·안전·제조 시험, 중소기업·근로자는 수용 기준과 실제 효과를 공동 정의해야 한다.

핵심 결론과 우선 추진할 연구

핵심 결론 5개

  1. 피지컬 AI 풀스택의 단위는 모델이 아니라 증거를 내는 폐루프다. 관측–상태–예측–계획–제어–결과–학습이 시간·접촉·안전·권리 계약으로 연결되고, 변경 뒤 보증을 재발행해야 한다.
  2. 더 많은 상상·계획·정밀도가 항상 더 좋은 행동을 만들지 않는다. R95·R100·R97은 objective, future, deployment transfer의 음의 전이를 보였다. 상황별 한계효용 gate를 별도 연구·검증해야 한다.
  3. 신체 전이는 pose가 아니라 접촉·시간 의미의 전이다. DexSuite·Tactus·wrench alignment·CoAWM·SwapBot은 body/tool/tactile/control-rate schema와 교정이 데이터 재사용의 전제임을 보강한다.
  4. 복구와 보증은 학습모델 밖의 독립 계층이어야 한다. task graph·feasibility oracle·runtime assurance가 계속 조건을 검사하되, condition sensor와 oracle 자체의 오류·만료도 시험해야 한다.
  5. 국가임무 성과는 도입 수와 현장 변화의 결합으로 입증한다. P13의 보급·투자 목표와 별개로 품질적합 무개입 완료, 안전·복구·전이·지연·전력·비용을 장비–공정–공장별 독립 hold-out에서 입증해야 한다.

우선 추진할 연구 5개와 이유 [제안]

  1. Marginal-Utility Runtime Orchestrator: fast/imagined path, 계획 반복, precision, edge/cloud를 같은 임무 효용으로 선택. R95·R100의 음의 전이를 직접 줄이는 상위 병목.
  2. Embodiment–Contact–Time Contract: body/tool ID, tactile calibration, wrench, 좌표, control rate, provenance를 공통 schema로 묶어 적응 데이터와 force violation을 측정. P12 데이터 생산을 재사용 가능한 자산으로 전환.
  3. Verified Local Repair with Fallible Observers: LOGIV형 dependency 복구에 condition uncertainty·oracle fault를 포함. false repair와 2차 위해를 전체 재시작 대비 검증.
  4. Capability–Resource–Assurance Evidence Card: 성공률·학습/배포 비용·serving trace·재현 근거·누락값을 machine-readable하게 공개. 공급자 선택과 현장 승인에서 evidence debt 방지.
  5. Factory-Scale Certificate Expiry & Regression: 장비→공정→공장 확대와 공급자 업데이트마다 certificate 유효범위·rollback·회귀영향을 자동 계산. P13의 단계별 실증을 임무 변화 증거로 연결.

국가임무 기여 경로와 검증 기준

경로: P1/P12/P13의 미션·실증·데이터 요구 → ETRI 공통 인터페이스·orchestrator·검증 harness → 대학의 원리·형식 보증 → 기업의 장비/공정 통합·serving trace → 타 출연연·독립기관의 도메인 hold-out → 중소 제조현장의 품질·안전·가동·작업자 부담·비용 변화. 이 역할 분담은 제안이며 공식 기관 배정이 아니다.

검증: 2028년 장비·공정별 3개월 baseline을 먼저 측정하고, 동일 작업·제품·교대에서 paired/동시 대조를 구성한다. success만이 아니라 qualified no-intervention completion, safety violation/exposure, false repair, recovery time, adaptation episode, unseen site/body transfer, p95/p99 latency, joule/mission, cost/qualified mission, evidence coverage, missed critical regression을 공개한다. 목표값은 baseline·위험 허용도·통계 검정력을 바탕으로 사전등록하며 정책 목표값을 임의로 변형하지 않는다.
