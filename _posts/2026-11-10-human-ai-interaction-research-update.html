PART 02 · T01

공동 작업을 목표와 논증의 공유 상태로 바라보기

기존 판단: 유지·확장 · 새 근거: P30·P31

1. Definition

작업 정의: 협업의 공유 상태는 참여자들이 같은 과업을 계속 참조하고 수정할 수 있게 하는 외부 표현이다. 목표는 무엇을 위해 일하는지, 논증은 왜 결론을 채택하는지를 드러내는 서로 다른 표현이다.

2. Problem Definition

분석 예시: 연구원이 보고서를 “간결하게” 고쳤지만 핵심 근거까지 빠졌다면 문장 요구와 보고 목적이 충돌한 것이다. 과업 완료뿐 아니라 수정이 상위 목적을 훼손했는지를 평가해야 한다.

3. Core Concepts

이 글에서는 목표·제약·성공 기준과 주장·근거·반론을 구별한다. 하나의 완성도 점수로 합치면 목적이 잘못된 경우와 논리 연결이 잘못된 경우를 분리하기 어렵다.

4. Introduction

문헌 추가: P30은 목표 표현 계층을, P31은 편집 가능한 논증 상태를 제안한다. 기존의 역할 배분·공통 기반 설명에 무엇을 공동으로 유지할 것인가라는 질문을 보완한다.

5. Motivation and Background

종합 해석: 좋은 협업에는 문맥을 많이 저장하는 것 외에 사람이 수정할 수 있는 참조 대상이 필요하다. 모든 대화를 구조화해야 한다는 주장 대신, 반복적으로 검토하는 핵심 대상부터 명시할 이유다.

6. Challenges

난점: 형식을 채우는 일이 목표 합의로 오인될 수 있다. 사용자가 모호함을 탐색하는 단계에서는 성급한 구조 고정이 오히려 대안 검토를 줄일 수 있다.

7. Research Questions

추가 질문: 같은 모델과 자료에서 공유 목표·논증이 재설명 부담과 결론 오류를 함께 줄이는가. 작성 시간 절약과 이해의 향상을 독립적으로 검증한다.

8. Approaches (Methods)

근거 수준: P30은 개념 제안이며 P31은 형성 평가다. 둘을 합쳐 협업 성능 향상의 인과적 증거로 계산하지 않는다. 직접 방법과 확인 범위는 근거표에 구분했다.

9. Key Applications

확장 제안: 연구기획의 사업 목적–근거–판단을 연결하고 검토자가 수정 이유를 남기게 할 수 있다. 이는 본 글의 업무 적용 구상이며 해당 기관에서 실증한 결과가 아니다.

10. Open Problems

미해결: 공유된 표현이 구성원의 실제 이해를 반영하는지 알기 어렵다. 수정된 목표를 다른 사람이 정확히 설명할 수 있는지 확인하는 과제가 필요하다.

11. Future Directions

제안: 대화만·공유 목표·공유 목표와 논증의 세 조건을 같은 정보량으로 비교한다. 이득이 자가보고 편의에만 나타나면 팀 성과 개선이라는 해석을 보류한다.

직접 근거와 확인 위치: P30 §2–5;Fig.1 / P31 §4–6;§8.1–8.2;§9.2–9.3

PART 02 · T02

주도권은 목표 수정권과 입력 통제권까지 포함

기존 판단: 유지·통제 범위 확장 · 새 근거: P30·P32

1. Definition

작업 정의: 주도권은 행동 승인 외에 자신의 목표를 확인·거부·변경하고 AI가 어떤 입력으로 적응하는지 선택할 수 있는 능력으로 분석한다. 이 구분은 본 글의 설계용 작업 정의다.

2. Problem Definition

분석 예시: 사용자는 보고서 편집을 맡겼지만 AI는 행동 이력에서 성과 평가 목적을 추정할 수 있다. 추정이 곧 위임으로 승격되는 순간 사용자가 승인하지 않은 기준이 작동한다.

3. Core Concepts

목표의 출처, 본인 승인 상태, 유효기간, 입력 사용 상태를 분리한다. 모델이 목표를 “알고 있다”는 주장과 그 목표에 따라 행동할 권한이 있다는 사실은 다르다.

4. Introduction

문헌 추가: P30은 추정된 목표와 명시적으로 지지된 목표를 구분한다. P32는 사용자가 말하지 않은 생체신호가 대화 적응의 입력이 될 수 있는 조건을 시험한다.

5. Motivation and Background

종합 해석: 기존의 중단·복구 기능만으로는 사용자가 어느 목표와 어느 입력에 동의했는지 설명하기 어렵다. 실행 전 목표 확인과 적응 입력의 설정도 통제 평가에 넣을 이유다.

6. Challenges

난점: 설정 화면은 실제 데이터 경로와 일치해야 한다. 수집을 끈 것인지 모델 입력에서 제외한 것인지, 과거 추론 상태까지 제거한 것인지 구분하지 않으면 통제의 의미가 불명확하다.

7. Research Questions

추가 질문: 사용자는 추정 목표를 발견하고 정정할 수 있는가. 입력을 끈 뒤 같은 생체 특징이 메모리나 요약을 통해 계속 사용되는지 검증할 수 있는가.

8. Approaches (Methods)

방법 구분: P30의 규범적 요구와 P32의 실험 결과는 성격이 다르다. 제안 실험에서는 목표 승인과 입력 차단을 별도의 조작으로 둬 어떤 기능이 효과를 내는지 분리한다.

9. Key Applications

확장 제안: 기관 업무 보조에서 추정 목표를 임시 상태로 표시하고 본인의 확인 뒤 공유하도록 할 수 있다. 생체신호 사용 자체를 업무 효과의 필요조건으로 가정하지 않는다.

10. Open Problems

미해결: 사용자가 한 번 승인한 목표가 바뀐 상황에도 유효한지 판단하기 어렵다. 확인 빈도가 늘어나는 비용과 잘못된 목표 적용의 비용을 함께 고려해야 한다.

11. Future Directions

제안: 정적 프로필·출처가 표시된 수정 가능 목표·목표 변경 시 재확인의 세 조건을 비교한다. 오래된 목표의 오적용이 줄지 않으면 실효 주도권 개선 가설은 미지지다.

직접 근거와 확인 위치: P30 §2–5;Fig.1 / P32 §4.1–4.6;§5.1–5.2 Table1;§8

PART 02 · T03

설득력 평정과 태도 변화의 다른 의미

기존 판단: 유지·신규 실험 추가 · 새 근거: P32

1. Definition

작업 정의: 설득력 평정은 상대 주장이 얼마나 설득적으로 느껴졌는지에 대한 평가다. 태도 방향 변화는 대화 전후 입장이 상대 쪽으로 움직였는지를 뜻하며, 둘 다 정답이나 공익을 보증하지 않는다.

2. Problem Definition

분석 예시: 설명이 설득적으로 들려도 입장을 바꾸지 않을 수 있다. 반대로 근거를 충분히 검토하지 않고 입장만 바꾸는 경우도 있으므로 선호를 판단 품질의 대리변수로 쓰기 어렵다.

3. Core Concepts

신뢰, 동의, 설득력, 변화의 방향, 변화의 지속성을 각각 측정한다. 특히 즉시 자기보고 변화와 시간이 지난 실제 행동을 같은 효과로 부르지 않는다.

4. Introduction

문헌 추가: P32는 생체신호 제공 조건에서 설득력과 즉시 태도 변화를 따로 분석한다. 아첨에 대한 기존 논의에 동의하는 반응이 아니어도 적응 방식이 영향을 줄 수 있다는 연구 축을 더한다.

5. Motivation and Background

종합 해석: 신뢰 조절 연구는 모델이 무슨 말을 하는지와 어떤 입력을 이용해 말투·전략을 바꾸는지를 함께 살펴야 한다. 하지만 생체 특징을 사용했다는 사실만으로 정교한 심리 추론을 입증하지는 않는다.

6. Challenges

난점: 개인별로 선택한 논쟁 주제와 초기 입장 강도가 다르다. 모델 종류·언어·반복 노출이 섞일 때 무엇을 비교했는지 분명히 해야 한다.

7. Research Questions

문헌 질문은 신호 접근과 고지 전후의 차이다. 추가 질문은 정보의 정확성과 논증 품질을 고정했을 때도 사용자가 입력의 영향을 이해하고 거부할 수 있는가이다.

8. Approaches (Methods)

직접 근거: 수치·모형·표본은 근거표에 제시했다. 고지가 항상 세션 후반에 이뤄졌으므로 고지 뒤 평정 하락을 고지 자체의 인과효과로 해석하지 않는다.

9. Key Applications

확장 제안: 정보 제공 인터페이스는 설득력보다 근거 확인·반례 검토·불확실성 이해를 일차 목표로 둘 수 있다. 이는 효과가 확인된 대안이 아니라 평가 설계 제안이다.

10. Open Problems

미해결: 더 큰 태도 변화가 도움이 되는지 판단하려면 주장의 타당성과 사용자의 숙고 과정을 알아야 한다. 변화의 크기만 최적화하는 평가는 방향을 잘못 잡을 수 있다.

11. Future Directions

제안: 동일한 검증 자료에서 입력 사용 여부와 고지 시점을 독립 배정한다. 고지의 효과가 순서 통제 후 사라지면 투명성의 인과적 보호 효과라는 가설을 기각한다.

직접 근거와 확인 위치: P32 §4.1–4.6;§5.1–5.2 Table1;§8

PART 02 · T04

설명을 공동 편집 가능한 논증으로 전환

기존 판단: 유지·구현 사례 추가 · 새 근거: P31

1. Definition

작업 정의: 논증 상태는 주장과 그 주장을 뒷받침하는 근거·연결 가정·조건·반론을 구별한 외부 표현이다. 모델 내부 계산의 충실한 설명을 뜻하는 것은 아니다.

2. Problem Definition

분석 예시: 두 문서가 같은 결론을 지지하더라도 적용 조건이 다를 수 있다. 조건을 문장 속에 묻어 두면 새 자료가 들어왔을 때 어느 결론을 바꿔야 하는지 찾기 어렵다.

3. Core Concepts

주장의 역할, 출처, 증거의 질은 별개다. 어떤 문장이 지지 근거로 연결됐다고 해서 그 출처의 방법론이 타당하거나 결론에 충분하다는 뜻은 아니다.

4. Introduction

문헌 추가: P31은 논증 구조를 사람과 LLM이 수정하는 공유 상태로 구현했다. 기존 편집 가능한 추론 논의에 문서 간 근거·가정·반론의 연결을 다루는 사례를 더한다.

5. Motivation and Background

종합 해석: 설명의 가치는 문장을 더 많이 보여주는 데만 있지 않다. 어느 가정을 거부했을 때 어떤 결론이 재검토 대상인지 사용자가 추적할 수 있어야 한다.

6. Challenges

난점: 구조가 깔끔하면 논리도 옳다고 느끼기 쉽다. 자동 분해의 누락과 잘못된 연결을 사람에게 검토 가능하게 드러내는 기능이 필요하다.

7. Research Questions

추가 질문: 완성된 논증을 자동 제시하는 방식보다 사람이 연결을 승인하는 방식이 장기 이해를 높이는가. 단순 조작 수 감소와 학습을 분리해서 시험한다.

8. Approaches (Methods)

직접 근거: P31 평가는 안내형 전문가 피드백이며 기존 인터페이스와의 성능 비교가 아니다. 더 빠르거나 더 정확한 의사결정을 입증했다고 기술하지 않는다.

9. Key Applications

확장 제안: 전략연구 제안서에서 필요성 주장·근거·적용 조건·반대 근거를 연결할 수 있다. 정책 부합 여부와 실증 성능의 근거를 같은 지지 관계로 뭉치지 않는 것이 설계 원칙이다.

10. Open Problems

미해결: 문헌 집합 밖의 반례는 그래프에 표시되지 않을 수 있다. 구조에 없는 근거가 실제로 없는지, 단지 검색하지 못했는지 구분할 표시가 필요하다.

11. Future Directions

제안: 대화·평면 근거표·편집 논증 그래프를 비교하고 새 반례에 대한 결론 수정 정확도를 측정한다. 완성도가 자가보고에서만 높으면 추론 개선 주장은 보류한다.

직접 근거와 확인 위치: P31 §4–6;§8.1–8.2;§9.2–9.3

PART 02 · T05

관계 효과를 기술·여력·정보로 세분화

기존 판단: 유지·이질성 분석 보완 · 새 근거: P33

1. Definition

작업 정의: 관계 역량은 관계를 만들고 유지하며 필요할 때 벗어나는 데 필요한 자원의 관점이다. 이 글에서는 개인의 고정 성격이나 임상 상태를 진단하는 명칭으로 사용하지 않는다.

2. Problem Definition

분석 예시: 대화 연습이 필요한 사람과 돌봄 때문에 시간이 부족한 사람은 같은 AI 기능을 다르게 사용할 수 있다. 사용 시간만으로 도움과 의존을 구분하기는 어렵다.

3. Core Concepts

P33이 구분한 기술·가용 여력·정보는 관계 사용의 이질성을 설명하는 개념이다. 여력이 부족한 상황을 개인 능력의 결함으로 바꿔 해석하지 않는다.

4. Introduction

문헌 추가: P33은 일반 목적 챗봇을 사회·정서적 목적으로 사용한 경험을 조사했다. 앞선 P29의 아첨 반응 양식 실험과 다른 질문을 다루며, 그 실험 결과를 상쇄하지 않는다.

5. Motivation and Background

종합 해석: AI가 모든 사람의 관계를 개선하거나 악화한다고 단정하기보다 어떤 필요를 보완하거나 대신하는지 구분해야 한다. 같은 기능도 사용 맥락에 따라 검증 목표가 달라진다.

6. Challenges

난점: 이미 사용하는 사람을 모집하면 사용하지 않거나 중단한 사람의 경험을 놓칠 수 있다. 스스로 보고한 도움이 독립적인 관계 개선을 뜻하는지도 불확실하다.

7. Research Questions

추가 질문: 연습 지원은 이후 AI 없는 대화 수행으로 이어지는가. 여력 부족을 덜어 준다는 보고가 실제 대인 소통의 지속과 함께 나타나는가.

8. Approaches (Methods)

직접 근거: P33은 목적표집과 횡단 자료를 바탕으로 개념을 구성했다. 장기 관계 악화나 개선의 인과 추정, 대표성 있는 유병률 추정에 사용하지 않는다.

9. Key Applications

확장 제안: 교육·업무 코칭에서 결과물을 대신 작성하는 기능과 스스로 수행하도록 연습시키는 기능을 비교할 수 있다. 치료 효과나 건강 조언의 권고로 확장하지 않는다.

10. Open Problems

미해결: 제안된 상태가 반복 측정에서 안정적으로 구분되는지, 사용자가 상황에 따라 어떻게 이동하는지는 별도 검증이 필요하다. 상태의 개수를 검증된 척도로 취급하지 않는다.

11. Future Directions

제안: 비민감 업무 대화에서 보조 전후와 지연 시점의 무보조 수행을 측정한다. AI 사용 중 만족도만 높고 무보조 수행은 나아지지 않으면 역량 보존 가설을 채택하지 않는다.

직접 근거와 확인 위치: P33 §3.1–3.4;§4–6;§7

PART 02 · T07

시스템 보장에는 표현·권한·집행의 구분 필요

기존 판단: 유지·상태 표현 확장 · 새 근거: P30·P31

1. Definition

작업 정의: 시스템 수준 분석은 목표와 근거가 어떻게 저장·변경되고 실제 실행으로 이어지는지 본다. 목표를 표현하는 계층과 그 목표에 맞게 행동하도록 강제하는 계층은 다르다.

2. Problem Definition

분석 예시: 승인된 목표를 정확히 저장했더라도 실행기가 예산이나 공개 범위를 어길 수 있다. 의미적 정합성과 실행 규칙 준수를 각각 검사해야 한다.

3. Core Concepts

목표 버전, 승인자, 적용 범위, 근거 연결, 실행 권한이 핵심 요소다. 데이터 그래프의 연결선이 곧 권한을 뜻하지 않도록 관계의 의미를 명시해야 한다.

4. Introduction

문헌 추가: P30·P31은 지속적 표현을 서로 다른 단위로 다룬다. 기존 P27의 메시지 운영 규칙에 무엇을 위해 실행하고 어떤 근거를 유지하는가라는 참조 상태를 보완한다.

5. Motivation and Background

종합 해석: 대화가 길어져도 구조화된 목표와 근거를 질의할 수 있다면 검토 기준을 보존하기 쉽다. 그러나 표현의 지속성이 정확성이나 정렬을 보장한다는 뜻은 아니다.

6. Challenges

난점: 개인 목표와 조직 목표가 충돌할 수 있다. 저장 형식보다 누가 추정·승인·공유·삭제할 수 있는지가 실제 운영에서는 더 중요한 제약이 될 수 있다.

7. Research Questions

추가 질문: 목표 변경이 어떤 문서와 실행 정책에 영향을 주는지 자동으로 찾을 수 있는가. 민감한 목표를 공유하지 않고도 협업에 필요한 제약만 전달할 수 있는가.

8. Approaches (Methods)

근거 수준: 새 두 논문은 범용 운영 보장의 실증 자료가 아니다. 제안 검증에서는 표현 오류와 권한 위반을 별도 오류 주입으로 만들고 탐지·방지 성능을 구분한다.

9. Key Applications

확장 제안: 사업 기획의 목적 변경 기록과 검토 근거를 연결하는 로컬 시스템으로 시작할 수 있다. 외부 게시·승인은 독립 권한 경계에서 수행되도록 설계한다.

10. Open Problems

미해결: 출처가 정정됐을 때 근거만 바꾸면 되는지 목표까지 재검토해야 하는지 자동 판정하기 어렵다. 사람이 결정해야 할 변경의 범위를 정의할 필요가 있다.

11. Future Directions

제안: 평면 메모·버전 목표표·목표와 논증 연결 그래프를 비교한다. 변경 영향 추적 이득이 저장량과 정보량 일치 후 사라지면 추가 구조의 필요성을 재검토한다.

직접 근거와 확인 위치: P30 §2–5;Fig.1 / P31 §4–6;§8.1–8.2;§9.2–9.3

PART 02 · T09

멀티모달·XR: 출력 외에 숨은 입력 경로 평가

기존 판단: 수정·입력 측면 추가 · 새 근거: P32

1. Definition

작업 정의: 멀티모달 상호작용에는 사용자가 보는 화면·음성뿐 아니라 시스템에 전달되는 센서 입력도 포함된다. 물리적 로봇의 행동 안전과 생체신호 적응의 영향을 혼동하지 않는다.

2. Problem Definition

분석 예시: 같은 헤드셋과 대화 화면을 사용해도 모델이 센서 특징을 받는지에 따라 입력 조건이 달라진다. 겉모습이 같은 인터페이스를 같은 처치로 볼 수 없는 이유다.

3. Core Concepts

센서 수집, 특징 계산, 모델 전달, 응답 적응, 고지와 철회를 분리한다. 어느 단계에서 신호가 끊겼는지 시험할 수 있어야 비감지 모드의 의미가 분명해진다.

4. Introduction

문헌 추가: P32는 VR 장치의 신호가 대화에 전달되는 조건을 다뤘다. 이를 HRI 전반의 성능이나 물리적 안전 결과로 확대하지 않고 입력 적응 사례로 한정한다.

5. Motivation and Background

종합 해석: 실감형 인터페이스의 유용성을 평가할 때 몰입감 외에 입력의 가시성과 선택권을 검토할 이유다. 더 많은 센서가 더 좋은 협업을 만든다고 가정해서는 안 된다.

6. Challenges

난점: 같은 생체 변화가 스트레스·집중·장치 불편 등 여러 원인에서 올 수 있다. 신호를 모델에 넣는 것과 감정을 정확하게 읽는 것은 별도의 주장이다.

7. Research Questions

추가 질문: 사용자가 센서 입력의 작동 여부를 정확히 예측할 수 있는가. 설명과 끄기 기능은 실측 데이터 흐름과 일치하는가.

8. Approaches (Methods)

직접 근거: P32에서 관찰한 즉시 반응은 특정 모델·소규모 대학 표본의 대화 결과다. 장치 자체의 이득이나 감정 인식 정확도를 검증했다고 서술하지 않는다.

9. Key Applications

확장 제안: 비민감 학습 안내에서 고정 인터페이스·명시적 사용자 입력·센서 적응을 비교할 수 있다. 센서 없는 비교군을 동등한 기능으로 제공하는 것이 연구 설계의 출발점이다.

10. Open Problems

미해결: 신호를 차단해도 이전 특징을 요약한 상태가 남을 수 있다. 철회 후 어떤 정보까지 삭제하는지를 모델 실행과 저장 정책 양쪽에서 확인해야 한다.

11. Future Directions

제안: 신호 수집·모델 전달·상태 저장을 분리한 모의 파이프라인을 먼저 감사한다. 끄기 후 전송이 남으면 사용자 통제 기능으로서 검증을 통과시키지 않는다.

직접 근거와 확인 위치: P32 §4.1–4.6;§5.1–5.2 Table1;§8

PART 02 · T10

평가 단위를 목표·논증·반복 사람 경험으로 구분

기존 판단: 유지·평가 대상 확장 · 새 근거: P30·P31·P32·P33

1. Definition

작업 정의: 상호작용 데이터는 무엇을 목표로 어떤 근거를 수정했고 어떤 입력을 사용했는지까지 기록할 수 있다. 데이터가 많다는 사실과 인과적으로 해석 가능한 설계는 다르다.

2. Problem Definition

분석 문제: 개념 제안·전문가 피드백·반복 대화 실험·횡단 사용 조사를 한 순위로 정렬할 수 없다. 각 연구가 답할 수 있는 질문을 먼저 구분해야 한다.

3. Core Concepts

사람 수, 대화 수, 시간, 표집 방법, 조건 배정, 분석 단위가 핵심이다. 한 사람이 여러 대화를 수행했다고 해서 독립 참가자가 늘어나는 것은 아니다.

4. Introduction

종합 해석: 이번 네 연구는 완성 답변 밖의 대상을 보게 한다. 다만 목표 표현의 잠재적 이득과 센서 적응의 즉시 효과를 동일한 검증 수준으로 설명해서는 안 된다.

5. Motivation and Background

설계 동기: 목표나 근거가 바뀌는 순간을 기록하면 최종 산출물만 볼 때 놓치는 오류를 평가할 수 있다. 이것은 본 글의 실험 제안이며 자동으로 평가 타당도가 확보되는 것은 아니다.

6. Challenges

난점: 실험 뒤 완성된 논증으로 이전 시점의 수정 필요성을 예측하면 누수가 생긴다. 예측 시점의 목표·근거·입력 상태만 노출하는 데이터 뷰가 필요하다.

7. Research Questions

추가 질문: 사용자가 수정한 목표와 근거는 후속 과제에서 더 적은 감독을 요구하는가. 같은 정보 예산의 단순 기록과 비교했을 때도 이득이 남는가.

8. Approaches (Methods)

근거 구분: P30에는 실증 효과 크기가 없고 P31에는 비교 성능이 없다. P32의 반복 대화는 참가자 내 의존성을 고려하며 P33의 횡단 자료로 시간에 따른 인과효과를 추정하지 않는다.

9. Key Applications

확장 제안: 문헌기획 과업에 목표 버전·근거 교체·승인 시점이 있는 합성 로그를 만들 수 있다. 실제 기밀 문서를 모으지 않고도 스키마와 누수 방지를 먼저 시험할 수 있다.

10. Open Problems

우선 R2-A의 오프라인 정정 추적과 정보량 통제를 검증하고, 다음 R1-G의 목표 변경 실험을 권한다. R4-S는 합성 센서 감사부터, R5-C는 반복 참여와 측정 부담 때문에 후속 단계로 둔다. 표본 수는 임의로 정하지 않고 파일럿 분산·참가자 내 상관·최소 의미 효과·탈락을 반영한 검정력 시뮬레이션으로 정한다. 참가자 동의·보상·중단권·개인정보 최소화·필요한 기관 심의를 거친 뒤 사람 대상 연구를 수행한다. 분석 전 주 지표·핵심 대비·허용 손실·제외·결측·중단·다중비교 규칙을 고정한다. 초기 R3·R4와 전체 원 제안은 원문 링크로 함께 제공한다.

즉시 품질·사용자 선호·실효 통제·장기 역량을 분리해 판정한다. 통계적으로 유의하지 않다는 사실을 동등함의 증거로 사용하지 않는다.

PART 05 · SCOPE & LIMITS

해석의 한계와 남은 후보

개념 제안·형성 평가·실험·횡단 조사에는 서로 다른 해석의 한계가 있다. 본문에서 인과·상관·선호·행동·장기 역량을 서로 대체하지 않았다. 새 4편은 초록뿐 아니라 명시한 방법·결과·논의 절을 확인했지만 참고문헌에 나오는 모든 원 연구까지 재검증한 것은 아니다.

이전 후보2611.01566은 오늘 공식 초록에 접근했으나 상세 가정·정리·실험을 검토하지 않아 확정 근거 수33편에 넣지 않았다. 2611.04692·2606.08274·2609.31138도 보류 목록을 유지한다. 검색 중 추가된 다른 후보 역시 본문 검토 없이 신규 결과로 소개하지 않았다.

검색엔진의 날짜 필터는 오래된 논문을 반환하기도 했다. arXiv 제출 이력과 공식 목록으로 대조했으며 목록 수록 시각을 최초 공개 시각으로 단정하지 않았다. 10개 주제의 최근 검색과 선택적 보완 조사이며 체계적 전수 고찰·메타분석이 아니다. 유료벽·색인 지연·초기29편 전체의 최신판 확인 공백은 남아 있다.
