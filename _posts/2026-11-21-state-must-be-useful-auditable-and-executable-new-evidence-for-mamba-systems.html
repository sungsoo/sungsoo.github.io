PART 01 · DEFINITION
01

Definition — 같은 “상태”라는 말이 가리키는 것들

Liquid Foundation Models(LFM)은 Liquid AI의 모델군이다. 반면 Mamba는 입력 의존 선택성을 가진 상태공간(sequence) 아키텍처다. LFM, Liquid Time-Constant Networks(LTC), Liquid Neural Networks(LNN), Mamba를 동일시하면 안 된다. LFM2는 공식 기술보고서가 밝힌 범위에서 입력 의존 게이트 단거리 합성곱과 일부 grouped-query attention(GQA)을 결합하지만, 이를 모든 LFM 세대나 다른 Liquid 계열 연구에 소급할 수 없다.

MambaFlowNP

Mamba-2의 다방향 scan과 conditional flow matching을 결합한 joint-predictive neural process다. 불규칙한 context와 query 점을 같은 Hilbert 기반 순서에 놓고, 각 query 위치에서 속도장을 읽는다.

MambaLIFT

VMamba의 기준 입력 대비 logit 차이를 공간 위치, VSS block, scan 방향, memory·selection·skip 등의 계산 경로로 분해하는 reference-based attribution 방법이다.

DS3M

compact nonlinear continuous-time state-space component를 병렬·직렬로 조합하고, 순차 적분을 Triton kernel에 융합하는 system-identification 모델이다. Mamba 논문은 아니며 SSM 하드웨어 공동설계의 인접 근거다.

상태의 세 역할

기억은 과거 정보를 압축하고, 추적은 시간이 흐르며 변하는 잠재변수를 갱신하며, 증거는 출력에 기여한 경로를 설명한다. 세 역할은 같지 않다.

구분MFNP가 모든 Mamba를 spatial model로 만든다는 뜻도, MambaLIFT의 relevance가 인과 효과라는 뜻도, DS3M의 이름에 state space가 들어간다고 Mamba라는 뜻도 아니다.

PART 03 · CORE CONCEPTS
03

Core Concepts — selective state, flow, attribution, fusion

3.1 선택적 SSM: 기억·망각·읽기의 입력별 조절

ht = Āt ht−1 + B̄t xt,    yt = Ct ht

선택성은 입력에 따라 Āt, B̄t, Ct가 달라져 무엇을 유지하고, 무엇을 쓰고, 무엇을 읽을지를 조절한다는 뜻이다. 이는 추론 중 가중치를 새로 학습한다는 뜻이 아니다. 순환 상태 크기가 sequence length와 무관하다는 말도 무한 정보를 완전하게 보존한다는 뜻이 아니다.

3.2 Query-local state: “한 상태”가 아니라 “읽을 위치”

전형적 terminal compression은 context를 하나의 최종 벡터로 압축한 뒤 모든 query가 이를 공유한다. MFNP는 context와 query를 공간적으로 직렬화하고 query token은 자기 위치에서 state를 읽되 쓰지 않는다. 따라서 같은 context, latent, routing offset에서 query set을 나누거나 합쳐도 다른 query의 예측을 바꾸지 않는 consistency를 목표로 한다. 단, joint predictive의 자유도는 공유 random-feature latent의 차원 F 이하라는 유한 제약을 갖는다.

3.3 Conditional flow matching과 reflow

LCFM(θ) = E || vθ(Yt, t, c) − dYt/dt ||²

conditional flow matching은 source distribution의 표본을 조건부 데이터 분포로 운반하는 velocity field를 학습한다. MFNP는 spatially correlated random-function source를 쓰고, teacher가 만든 결합 표본으로 한 차례 reflow distillation을 수행해 1-step Euler student를 만든다. 따라서 보고된 end-to-end speedup은 linear scan 효과와 sampling-step 감소 효과의 합성이다.

3.4 Conservation은 accounting, intervention은 causality에 더 가깝다

Σp Rc(p) = fc(x) − fc(x⁰)

MambaLIFT의 completeness는 relevance 총합이 기준 입력 대비 logit 차이를 재구성한다는 회계적 성질이다. 같은 총합을 보존하는 여러 interaction allocation과 temporal propagation rule이 서로 다른 heatmap을 만들 수 있다. 특정 memory path를 실제로 되돌렸을 때의 출력 변화는 비선형 상호작용 때문에 relevance의 단순 합과 다를 수 있다.

3.5 Kernel fusion: 계산량과 실행 시간 사이의 층

연속시간 system identification은 한 sampling step마다 RK4처럼 여러 vector-field evaluation을 요구한다. 작은 네트워크를 수백 번 순차 호출하면 arithmetic보다 launch와 memory movement가 병목이 된다. DS3M은 compact component의 상태 전파·적분을 한 Triton program에 묶는다. 그러나 weight가 SRAM에 들어가야 하고 구조를 미리 알아야 하므로 “아무 모델에나 적용되는 가속”이 아니다.

PART 04 · INTRODUCTION
04

Introduction — 연구 질문이 연산자에서 상태의 책임으로 이동한다

11월 19일 글은 안정성 bound, native 2D dynamics, scan order를 “시스템 속성”으로 묶었고, 11월 20일 글은 CoScan과 Slim-Mamba를 통해 적응성을 어디에 배치할지 물었다. 이번 업데이트는 그 다음 단계다. 적응적 state를 만들었다면 어느 query가 어떤 state를 읽는가, 그 state의 기여를 어떻게 감사하는가, 그리고 반복 recurrence를 어떻게 장치에 매핑하는가를 답해야 한다.

통합 해석연구 흐름은 효율적인 연산자 자체에서 기억 회수·상태 추적·검증 가능한 설명·하드웨어/학습 공동설계로 이동하고 있다. 이번 세 논문은 이 이동을 각각 spatial prediction, visual attribution, nonlinear dynamics에서 보여준다.

이 글은 논문 간 직접 비교를 하지 않는다. MFNP는 probabilistic spatial interpolation, MambaLIFT는 XAI, DS3M은 nonlinear system identification을 다룬다. 각 결과는 저자 보고이며 독립 재현이 아니다. 특히 어느 모델도 모든 데이터 크기·하드웨어·정밀도·업무에서 우월하다고 해석하지 않는다.

PART 05 · MOTIVATION AND BACKGROUND
05

Motivation and Background — 복잡도 표기만으로는 부족하다

표준 full attention의 prefill 연산은 길이 L에 대해 이차이며, KV cache는 길이에 선형으로 증가하고, decode 한 토큰의 attention은 누적 이력 길이에 선형이다. GQA는 KV head 수를 줄여 계수를 낮추지만 길이 의존을 없애지 않는다. 고정 상태 크기의 순수 SSM은 총 sequence 연산이 선형이고 recurrent inference state가 길이에 독립적일 수 있다.

그러나 LFM2처럼 short convolution과 일부 GQA를 섞은 hybrid 전체를 O(1) memory나 완전 선형이라고 부르면 안 된다. MambaFlowNP도 training activation 전체가 항상 상수라는 뜻이 아니다. 저자 주장은 fixed feature/state/depth에서 forward compute가 O(K)라는 범위다. Hilbert key sorting은 운영 범위에서 선형으로 취급되지만 일반적인 비교 기반 sort의 보편적 복잡도 주장과 같지 않다.

PART 06 · CHALLENGES
06

Challenges — 압축, 순서, 설명, 커널이 서로의 오차를 숨긴다

장거리 정확 회수 vs 압축

고정 크기 state는 memory traffic을 줄이지만 query별 세부 evidence를 잃을 수 있다. “기억한다”와 “상태를 추적한다”를 분리해 측정해야 한다.

불규칙 geometry vs 1D scan

Hilbert·Morton·lexicographic order는 이웃을 다르게 보존한다. 순서는 모델 바깥 전처리가 아니라 inductive bias다.

완전성 vs 설명의 유일성

합계가 맞아도 interaction 분배와 reference 선택에 따라 attribution map이 변한다. perturbation 방식도 순위를 바꿀 수 있다.

선형 compute vs 실제 latency

짧은 sequence에서는 dispatch floor가 지배하고, 긴 recurrence에서는 launch·SRAM·memory movement가 지배한다.

저정밀 장기 안정성

상태 갱신 오차는 시간축으로 누적될 수 있다. 이번 연구는 INT8/INT4 장기 drift나 reset 정책을 충분히 다루지 않는다.

효과 분리

architecture, data, distillation, solver, precision, kernel 효과를 분리하지 않으면 큰 speedup을 잘못 귀속한다.

핵심 난제MFNP의 114–784×는 1-step reflow와 linear scan이 함께 만든 end-to-end 결과다. 작은 K에서 1-NFE를 맞추면 FNP·NDP·MFNP가 비슷한 dispatch floor에 놓이고, 큰 K에서 attention의 이차 비용이 갈라진다. 이 분해가 없으면 “Mamba라서 수백 배”라는 과장으로 이어진다.

PART 08 · APPROACHES (METHODS)
08

Approaches — 세 논문의 방법, 결과, 제한을 연결해 읽기

8.1 MambaFlowNP: terminal compression 대신 위치별 state를 읽는다

방법context value와 noisy query slice를 frozen random Fourier coordinate feature와 함께 token화한다. 두 Hilbert ordering과 역순을 합쳐 네 방향으로 route하고, distance-aware Mamba-2 scan을 공유 parameter로 실행한다. context token은 state에 쓰고 query token은 zero input·zero step size로 자기 위치 state를 읽기만 한다. per-direction state를 원래 point order로 되돌려 fuse한 뒤 query velocity를 출력한다.

학습CFM teacher 80k step, reflow student 20k step을 사용한다. NOAA에는 최대 40k step의 CRPS fine-tuning이 추가된다. baseline은 100k step이며 CRPS 단계가 없다. 모든 train/evaluation은 NVIDIA L40S에서 수행되고, 각 model-task cell은 train과 10 evaluation seed를 합쳐 100 GPU-hour cap을 둔다.

8.2 MambaLIFT: selective scan을 경로별로 감사하되 인과라고 부르지 않는다

방법VMamba의 class-logit 차이 fc(x)−fc(x⁰)를 multiplier-first rule로 역전파한다. selective injection τtBtut의 3-factor interaction, state carry, readout, D-skip, LayerNorm, CrossScan/CrossMerge, residual fan-out을 각각 처리하고 공유 source에서는 consumer multiplier를 한 번만 합친다.

검증ImageNet-1K의 1,000-image calibration set에서 γ와 reference를 고정하고, 별도 1,000-image held-out set에서 VMamba-T/B를 평가했다. 138/194개 audited interface의 최악 상대 보존 오차는 float64 내부에서 1.7×10⁻¹⁵/1.5×10⁻¹⁵였고, 원래 float32 model의 Δlogit과 relevance 합의 상대오차는 1.2×10⁻⁷/1.8×10⁻⁷이었다.

핵심 반례보존되는 exact allocation도 서로 다른 attribution map을 만들었다. memory·selection·content·skip에 대한 local intervention correlation은 대체로 낮았고, global memory intervention–relevance correlation은 0.42–0.45였다. 정확한 relevance 회계는 finite intervention 효과나 causal validity를 보장하지 않는다.

비용·제한RTX 5060 8GB에서 MambaLIFT 4-reference sequential 설명은 VMamba-T/B당 8.66/12.9초로, MambaLRP 0.056/0.082초보다 훨씬 비쌌다. float64와 reference별 backward가 원인이라 matched-precision 비교가 아니다. 더 큰 state, gated SS2D, 다른 selective SSM으로의 일반화도 미확립이다.

8.3 DS3M: recurrence를 바꾸기보다 실행 단위를 바꾼다

방법SUBNET encoder가 짧은 input/output history에서 초기 state를 추정한다. 여러 compact continuous-time nonlinear component를 병렬 head와 직렬 block으로 구성하고, explicit integrator를 포함한 반복 평가를 Triton kernel에 fuse한다. port-Hamiltonian variant도 제시한다.

저자 보고RTX 3090, PyTorch 2.11.0+cu126, Triton 3.6.0, float32에서 CT-SUBNET forward+backward microbenchmark는 T=100/200에서 CUDA eager 대비 151.91×/159.82×, compiled CUDA 대비 42.79×/40.73× 빨랐다. Wiener–Hammerstein에서는 DS3M이 RMSE 0.24mV를 1.5시간에 보고했고, SUBNET은 같은 0.24mV에 200시간 이상을 표기했다.

제한일부 benchmark training time은 서로 다른 hardware의 문헌값이라 공정한 wall-clock 대조가 아니다. fused program 때문에 weight가 관련 SRAM에 들어갈 만큼 작고 network architecture가 미리 정해져야 한다. Silverbox의 distribution-shift trajectory에서 SUBNET 계열의 약점도 남았다. 따라서 kernel fusion은 보편적 모델 우위가 아니라 특정 크기·구조·장치의 공동설계 결과다.

통합 결론MFNP는 “무엇을 보존해야 하는가”를 위치별 state access로, MambaLIFT는 “어떤 경로가 기여했는가”를 회계와 intervention의 분리로, DS3M은 “어떻게 실행할 것인가”를 kernel fusion과 memory hierarchy로 구체화한다.

PART 10 · OPEN PROBLEMS
10

Open Problems — 유한 상태의 한계와 실패를 관찰하는 법

  • 과제별 기억 한계: 어떤 query family에서 유한 state가 충분하고, 언제 external memory나 attention이 필수인가?
  • 망각 탐지: state가 결정적 evidence를 잃었다는 사실을 출력 오류 이전에 탐지할 수 있는가?
  • 장기 session drift/reset: reset이 필요한 시점과 보존해야 할 invariant를 어떻게 분리할 것인가?
  • 설명의 인과 타당성: relevance accounting과 intervention effect를 연결하는 interaction-aware counterfactual test가 필요하다.
  • 훈련 길이 밖 일반화: 더 긴 sequence, 더 조밀한 point set, 새로운 geography, 새로운 dynamics regime에서 무엇이 붕괴하는가?
  • 양자화 누적 오차: INT8/INT4 state와 complex/MIMO transition에서 장기 안정성을 어떻게 보증할 것인가?
  • 공정 비교: 동일 데이터·split·training update·solver NFE·precision·batch·hardware·power mode로 architecture와 distillation 효과를 분리해야 한다.
  • 한국어 전문업무와 실세계 안전: 장기 문서, 설비 log, 다중 센서에서 근거 회수와 오류 복구가 검증되지 않았다.

미해결state가 작다는 것은 비용에 대한 장점이지, 기억의 충분성·설명의 정당성·안전성에 대한 증명이 아니다.

PART 11 · FUTURE DIRECTIONS
11

Future Directions — 압축 state, 선택적 evidence, 검증 가능한 실행의 계층화

11.1 계층형 기억 시스템

제안항상 갱신되는 compact state, 필요 구간만 여는 sparse/local attention, 출처와 시간을 보존하는 external evidence memory를 계층화한다. query-local state는 즉시 추적에, attention은 exact local retrieval에, external memory는 장기 증거에 맡긴다. evidence가 부족하다고 판단될 때만 memory budget을 늘리는 adaptive allocation을 학습한다.

11.2 “설명 생성”과 “설명 검증”을 분리한다

제안conservation-based attribution을 빠른 audit ledger로 사용하되, 중요한 결정에는 reference ensemble, replacement robustness, mechanism intervention, counterfactual replay를 통과시킨다. explanation latency와 peak memory도 시스템 SLO에 포함한다.

11.3 성공 작업당 비용 benchmark

제안token/s 대신 Joule/success · p95 latency · peak memory · evidence recall · error-recovery rate를 함께 보고한다. 동일한 quantization, batch, thermal state, compiler, kernel version을 고정하고 failure case를 포함한다.

11.4 ETRI 온디바이스 협업지능 단계적 검증안

  1. 단계 1 — 통제 비교: 동일 학습 데이터·parameter budget·quantization·hardware에서 full attention, pure SSM, hybrid, external-memory system을 비교한다.
  2. 단계 2 — 오염 시험: sensor dropout, adversarial ordering, state contamination, quantization drift, communication loss를 주입하고 망각 탐지·reset·fallback을 평가한다.
  3. 단계 3 — 감사 시험: relevance conservation, evidence retrieval, intervention consistency, human operator diagnosis time을 함께 측정한다.
  4. 단계 4 — 장기 실증: robot·설비에서 수일~수개월의 drift, maintenance event, topology change를 포함해 성공 작업당 에너지와 안전한 복구를 검증한다.
최종 제안다음 세대 state-space system의 경쟁력은 “얼마나 긴 문맥을 처리하는가”보다 필요한 상태를 위치별로 제공하고, 그 사용을 감사하며, 실패 시 복구 가능한 비용으로 실행하는가에서 결정될 가능성이 크다. 이는 현재 근거에서 도출한 연구 제안이지 이미 입증된 보편 법칙은 아니다.
