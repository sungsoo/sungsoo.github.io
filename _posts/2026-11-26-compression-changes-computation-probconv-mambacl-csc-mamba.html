THE CENTRAL QUESTION

토큰이나 센서 측정값을 줄였을 때, 모델은 단지 더 짧은 입력을 처리하는가—아니면 전혀 다른 계산을 수행하는가?

이번 신규 근거의 공통 결론은 후자에 가깝다. 토큰 제거는 합성곱 이웃과 순환 상태 업데이트 위치를 바꾸고, 측정 압축은 모델이 처음부터 볼 수 있는 증거를 바꾸며, 의료영상의 구조적 사전은 어떤 교차 모달 정보가 융합 가능한지를 제한한다.

PART 01 · DEFINITION
01

Definition

세 종류의 압축, 세 종류의 계산 변화

토큰 압축(token compaction)은 중간 표현에서 일부 토큰을 실제로 제거해 후속 층이 더 짧은 시퀀스를 처리하게 한다. 0으로 마스킹하고 자리를 남기는 token masking과 다르다. Mamba 계열처럼 국소 합성곱과 순환 상태 업데이트를 함께 쓰는 모델에서는 토큰을 제거하면 살아남은 토큰의 이웃과 상태 전이 횟수가 모두 바뀐다.

재구성 없는 압축학습(reconstruction-free compressive learning)은 원 영상을 복원하지 않고 저차원 센서 측정값에서 곧바로 분류한다. MambaCL은 학습 가능한 block-wise sensing, 서로 다른 압축률을 공통 차원으로 투영하는 FLP, 사전학습 Vision Mamba를 결합한다.

구조 유도 복원(structure-guided reconstruction)은 단순히 입력을 줄이는 일이 아니다. CSC-Mamba는 MRI의 저해상도 목표 contrast와 고해상도 참조 contrast 사이의 공유 구조를 convolutional sparse coding 목적함수로 제한하고, Vision Mamba로 전역 문맥을 보강한다.

SCOPELFM은 Liquid AI의 모델군이고 Mamba는 선택적 상태공간 아키텍처다. 이번 세 논문은 Mamba·Vision Mamba 응용을 다루며 LFM2/LFM3를 평가하지 않는다. LFM=LTC=LNN=Mamba라는 동일시는 틀리고, LFM2의 gated short convolution+GQA 구조를 다른 LFM 세대나 Mamba에 소급하지 않는다.
PART 02 · PROBLEM
02

Problem Definition

공통 설계 문제는 긴 이력 또는 넓은 공간 문맥을 유지하면서 입력·토큰·연산량을 줄이는 것이다. 그러나 압축률만 최대화하면 중요한 증거를 잃고, 정확도만 최대화하면 실제 단말 예산을 넘는다. 따라서 목표는 다음과 같은 제약 최적화로 보아야 한다.

maximize Q(task, evidence retained) subject to p95 latency ≤ L*, peak memory ≤ M*, energy/task ≤ E*, sensing/transmission cost ≤ S*

여기서 더 어려운 점은 압축이 입력 크기뿐 아니라 연산자의 의미까지 바꾼다는 사실이다. Mamba에서 토큰 하나를 제거하면 depthwise convolution의 오프셋이 재배열되고, 그 위치에서 수행됐을 상태 decay와 write도 사라진다. 영상 센싱률을 낮추면 후속 모델은 복원 가능한 전체 영상이 아니라 강하게 혼합된 측정값만 본다. MRI 참조 영상을 무제약으로 융합하면 목표 contrast에 없는 texture를 복사할 수 있다.

INTERPRETATION연구 흐름은 “효율적인 선형 연산자”에서 “무엇을 남길지, 남긴 뒤 계산이 어떻게 달라지는지, 그 계산이 하드웨어에서 실제로 이득인지”를 함께 설계하는 단계로 이동하고 있다.
PART 03 · MECHANISMS
03

Core Concepts

선택적 상태공간 모델: 선택성은 추론 중 학습이 아니다

hₜ = Āₜ hₜ₋₁ + B̄ₜ xₜ,    yₜ = Cₜ hₜ

입력 의존적인 Āₜ, B̄ₜ, Cₜ는 각 위치에서 무엇을 기억·망각·읽을지 조절한다. 이는 고정된 학습 가중치가 입력에 따라 다른 계수를 생성하는 것이며 추론 중 가중치를 다시 학습하는 과정이 아니다. 고정 크기 순환 상태가 시퀀스 길이에 독립이라는 말도 무한 정보를 완전 보존한다는 뜻이 아니다.

ProbConv: 제거 뒤의 이웃을 기대값으로 학습한다

keep probability pₜ와 독립 Bernoulli 결정 mₜ를 두면 ProbConv는 살아남은 위치에서 압축된 합성곱 창의 pre-activation 기대값을 계산한다.

ProbConv(x,p)ₜ = w₀ ⊙ xₜ + Σᵣ₌₁ᴷ⁻¹ wᵣ ⊙ aₜ₋₁⁽ʳ⁾
aₜ⁽¹⁾ = pₜxₜ + (1−pₜ)aₜ₋₁⁽¹⁾;   aₜ⁽ʳ⁾ = pₜaₜ₋₁⁽ʳ⁻¹⁾ + (1−pₜ)aₜ₋₁⁽ʳ⁾

pₜ=1이면 토큰을 창 앞에 넣고 오래된 이웃을 한 칸 밀며, pₜ=0이면 창을 그대로 둔다. 상태공간 step Δₜ를 pₜΔₜ로 gate하면 drop된 위치에서 decay와 write를 건너뛴다. 저자들은 binary p에서 ProbConv+step gating이 실제 압축 Mamba/Mamba-2 block의 retained-position 출력을 재현한다고 증명한다.

측정 토큰과 희소 사전

MambaCL은 B×B 블록 xᵢ에 학습 가능한 선형 sensing matrix Φg를 적용해 yᵢ=Φg xᵢ를 만들고, 압축률별 측정 차원을 공통 embedding으로 투영한다. Mixup은 동일 선형 sensing operator 아래에서 센싱 전 혼합과 교환되지만, token-level CutMix는 영상 공간의 사각형 CutMix와 동일하지 않다.

CSC-Mamba의 핵심은 공유 구조를 α와 참조 sparse code αz의 ℓ₁–ℓ₁ 근접성으로 제한하는 것이다. 즉 “참조 영상을 보라”가 아니라 “공유 가능한 sparse structure만 가져오고 목표 contrast 고유 성분은 별도로 보존하라”는 명시적 prior다.

PART 05 · CONTEXT
05

Motivation and Background

Mamba 원논문은 2023년 최초 공개된 배경 연구다. 선택적 scan과 hardware-aware implementation을 결합해 고정 상태 크기에서 전체 시퀀스 연산을 길이에 선형으로 구성했다. Mamba-2는 structured state space duality로 recurrent/attention 관점을 연결했고, Mamba-3은 2026년에 exponential–trapezoidal discretization, complex state, MIMO를 제안했다. 이번 세 연구는 이 계보의 새 세대 모델을 제안하기보다, 기존 Mamba/Vision Mamba를 압축된 계산 그래프와 도메인 prior에 배치한다.

표준 full attention은 prefill에서 길이에 대해 이차 연산, KV cache에서 선형 메모리, 한 토큰 decode attention에서 이력 길이에 선형 비용을 갖는다. 고정 상태 크기 순수 SSM은 총 연산을 O(T), 순환 상태를 길이에 대해 O(1)로 둘 수 있다. 그러나 이 asymptotic 차이가 모든 실제 길이·batch·kernel에서 즉시 속도 우위가 되지는 않는다.

BOUNDARYGQA는 KV cache의 계수를 줄이지만 길이에 대한 선형 의존을 없애지 않는다. LFM2처럼 short convolution과 일부 GQA를 혼합한 모델 전체를 O(1) memory 또는 완전 선형이라고 부를 수 없다. ProbConv의 압축 결과도 LFM 구조에 자동 적용할 수 없다.
PART 06 · FAILURE MODES
06

Challenges

Train–deploy mismatch

zero mask는 빈 slot을 남긴다. physical compaction은 이웃을 당기고 state update를 삭제한다. soft selector가 좋은 점수를 내도 hard top-k 배포와 다른 network를 학습할 수 있다.

정확 회수와 압축의 충돌

압축률이 높을수록 증거가 줄고 한 측정값에 정보가 더 강하게 혼합된다. 상태가 task-relevant summary를 유지하는지와 원 정보를 복원할 수 있는지는 다른 질문이다.

Asymptotic vs. measured speed

짧은 시퀀스에서는 최적화된 attention kernel이 selective scan보다 빠를 수 있다. kernel launch, batch, precision, GPU가 crossover를 결정한다.

Prior vs. hallucination

참조 MRI contrast의 구조를 쓰면 복원이 쉬워지지만 목표 contrast에 없는 texture를 복사할 수 있다. explicit prior도 잘못된 guidance나 pathology shift에서 안전하다고 보장하지 않는다.

Quantization·noise accumulation

측정 noise와 저정밀 순환 오차는 서로 다른 단계에서 누적된다. MambaCL의 σ는 measurement energy로 정규화되지 않아 ratio 간 SNR 공정 비교가 아니다.

재현성과 attribution

checkpoint, pretraining, projection, optimizer가 다른 complete-system 비교는 selective SSM 하나의 효과를 분리하지 못한다. 공개 코드와 고정 commit이 필수다.

PART 08 · APPROACHES
08

Approaches (Methods)

8.1 ProbConv: 실행할 압축 network를 학습한다

ProbConv는 keep probability 아래에서 압축된 causal convolution window의 정확한 pre-activation expectation을 선형 scan으로 계산한다. step gating은 pₜ=0일 때 A transition의 decay를 identity로, write를 0으로 만들어 해당 state step을 건너뛴다. straight-through top-k를 쓰면 forward는 hard budget, backward는 relaxed operator의 gradient를 selector로 보낸다.

AUTHOR-REPORTEDVim-Tiny/ImageNet에서 ρ=0.35일 때 ProbConv top-1은 71.59±0.12%, zero mask+step gating은 67.87±0.32%였다. soft-forward와 hard compaction의 gap은 ProbConv +0.08±0.05 point, zero-mask+step gating +1.98±0.25 point다. Cobra-3B의 dense LM FLOPs 10% budget에서 six-benchmark mean은 ProbConv 61.1±0.2, zero-mask+step gating 58.4±0.2, layer-0 Δ 58.6이었다.

배포 속도는 batch 조건에 민감했다. 저자 보고 tight budget에서 Vim은 RTX 4090 fp32로 1.61×, VideoMamba는 RTX 4090 bf16 synthetic input으로 2.04×, Cobra prefill은 H100 bf16 synthetic input으로 2.84× 빨랐다. 그러나 batch 1에서는 kernel launch overhead가 Vim/VideoMamba의 절감을 상쇄했다. training은 dense length로 수행한다.

LIMITbinary mask equivalence는 강한 결과지만 fractional keep의 exact deployed equivalence는 아니다. fixed budget은 keep 결정을 결합시키지만 기대 window는 독립 Bernoulli를 가정한다. 논문이 제시한 코드 URL은 실행일 현재 GitHub API에서 404였으므로 독립 재현은 아직 확인하지 못했다.

8.2 MambaCL: 센싱부터 분류까지 한 pipeline으로 학습한다

MambaCL의 CSM은 영상 블록을 낮은 차원의 측정 토큰으로 바꾸고, nested row를 공유하는 sensing base matrix로 25%, 10%, 1.8%의 preset ratio를 지원한다. FLP는 비율별 측정 차원을 동일 embedding으로 맞춘다. native patch embedding은 우회하고 ImageNet-1K pretrained Vim의 bidirectional selective scan을 fine-tune한다. training은 PyTorch 2.1, RTX 3090 Ti 24GB, 300 epochs, batch 64, AdamW, seed 0/1/2다.

AUTHOR-REPORTEDCIFAR-10 1.8% CS에서 MambaCL-B는 72.61±0.09%, TransCL-32는 69.42±0.07%였다. 그러나 MambaCL-B는 91.58M params·12.61G FLOPs로 TransCL-32의 87.78M·8.72G보다 크다. MambaCL-S는 23.83M·3.34G로 작고, ImageNet-1K에서는 81.58±0.15%로 TransCL-32의 81.48±0.15%보다 0.10 point 높았다. 통계적 우월성은 확립되지 않았다.

224×224 batch-1 latency는 TransCL-32가 0.218 ms/image로 MambaCL-Ti 0.316, S 0.637, B 1.451보다 빨랐다. 384×384에서 MambaCL latency 증가율은 token length 2.94× 증가에 가까운 약 3×였지만 두 해상도만으로 end-to-end linear scaling을 증명하지는 못한다.

8.3 CSC-Mamba: 명시적 구조 prior와 전역 refinement

CSC-Mamba는 저해상도 T2 target과 고해상도 PD guidance를 ACSC로 sparse code화하고, LeSITA deep unfolding으로 공유 구조를 융합한다. LR-specific branch와 fused HR branch를 각각 Vision Mamba로 한 번 refinement한 뒤 별도 convolutional dictionary로 복원해 합친다. 연구는 IXI healthy-subject 576 scans를 subject-wise로 나눠 23,000/5,700/2,930 slices로 학습·검증·시험했고 RTX 4060 Ti에서 100 epochs 학습했다.

AUTHOR-REPORTED×2 SR에서 CSC-Mamba는 PSNR 42.57 dB, SSIM 0.9843, 52 ms였고 strongest reported CD-DPE는 42.08, 0.9821, 98 ms였다. ×4에서는 38.76 dB/0.9681로 CD-DPE 38.14/0.9668보다 높았다. 이는 동일 test set·preprocessing 아래의 저자 보고 비교지만 seed 분산, 병원 외부검증, pathology subgroup은 보고되지 않았다.

PART 09 · APPLICATIONS
09

Key Applications

온디바이스 비전·영상·음성. 입력마다 불필요한 patch, video token, speech frame을 물리적으로 제거하면 후속 block의 연산과 memory movement를 줄일 수 있다. 단, selector와 compaction kernel을 같은 하드웨어에서 함께 측정해야 한다.

센서–모델 공동설계. compressive camera, 저대역폭 edge sensor, semantic communication에서는 전체 신호를 획득·복원한 뒤 모델을 압축하는 대신 task에 필요한 measurement만 획득할 수 있다. MambaCL은 이 방향의 분류 근거지만 bit rate, ADC, sensing energy를 아직 닫지 못했다.

의료영상 가속. 빠른 고해상도 contrast를 guidance로 쓰고 느린 contrast를 저해상도로 획득하면 scan time을 줄일 가능성이 있다. CSC-Mamba는 explicit prior+global context의 가능성을 보였지만 실제 acquisition protocol, motion, pathology, scanner shift 검증이 선행돼야 한다.

로컬 멀티모달 보조와 RAG. 이미지·영상 토큰을 질의 조건에 따라 줄여 prefill을 가속할 수 있다. 정확한 근거 회수 구간을 잘못 제거하면 hallucination이 늘 수 있으므로 evidence retention을 별도 지표로 둬야 한다.

PROPOSAL · ETRI/PHYSICAL AI센서 상태 추적, 로봇 고수준 계획, 엣지 운영지능에서 observation token을 적응적으로 압축하되, 위험 이벤트·통신 단절·상태 변화 시 budget을 복원하는 controller를 연구할 수 있다. 이는 창의적 연구 제안이며 ProbConv/MambaCL/CSC-Mamba가 로봇 저수준 제어 안전성을 검증했다는 뜻이 아니다.
PART 10 · OPEN PROBLEMS
10

Open Problems

  • 유한 상태와 유한 토큰 budget의 과제별 기억 한계: 제거된 증거가 언제 회복 불가능해지는지 예측하는 bound가 부족하다.
  • 망각 탐지: selector가 중요한 토큰을 버린 사실을 모델 자체가 감지하고 원본·외부 memory를 다시 호출할 수 있어야 한다.
  • 장기 세션 drift/reset: 반복 compaction, quantization, state carry가 길이 밖 일반화에서 만드는 오류를 측정해야 한다.
  • 공정한 비교: 동일 data, pretraining, optimizer, sensing matrix, kernel maturity, precision, batch에서 attention·Mamba·hybrid를 비교해야 한다.
  • 실세계 비용: FLOPs와 GPU kernel latency 외에 센서 획득, memory traffic, 통신, selector, 오류복구 비용이 빠져 있다.
  • 의료 안전성: healthy IXI의 PSNR/SSIM이 병변 보존과 판독 성공을 보장하지 않는다. hallucination·texture copying·uncertainty audit가 필요하다.
  • 재현성: ProbConv의 선언된 코드 URL은 현재 접근되지 않고, MambaCL은 data available on request로 표기한다. 독립 재현 전에는 성능 수치를 저자 보고로 유지해야 한다.
  • 한국어 전문업무: 압축된 멀티모달 근거가 한국어 질의, 표·도면, 규정·정책 문서에서 인용 정확도를 유지하는지 미검증이다.
PART 11 · FUTURE DIRECTIONS
11

Future Directions

계층형 증거 예산: state + local attention + external memory

PROPOSAL기본 흐름은 압축 상태가 처리하고, selector uncertainty가 높거나 exact retrieval이 필요한 구간만 local/full attention으로 보내며, 삭제된 원본은 외부 evidence memory에서 재호출하는 계층형 system이 유망하다. 핵심은 compression policy와 recovery policy를 함께 학습하는 것이다.

필요할 때만 커지는 적응형 budget

토큰 keep ratio, 센싱 측정 수, recurrent state rank, attention window를 서로 독립된 hyperparameter가 아니라 task risk에 반응하는 공동 budget으로 만들 수 있다. 다만 budget controller의 실패가 본 모델보다 더 큰 안전 위험이 될 수 있으므로 conservative fallback이 필요하다.

성공 작업당 시스템 benchmark

다음 benchmark는 Joule/성공 작업, p95 latency, peak memory, 근거 회수율, 오류복구율을 함께 보고해야 한다. 평균 throughput만으로는 rare failure와 실시간 deadline miss를 숨길 수 있다. 측정 조건에는 하드웨어, batch, precision, context/token budget, sensor pipeline, kernel version을 포함해야 한다.

ETRI 온디바이스 협업지능 단계적 검증

  1. 동일 조건 실험: 같은 training data·quantization·hardware에서 Mamba-2/3, hybrid, Transformer, ProbConv/zero-mask 비교.
  2. 상태·통신 강건성: token pollution, sensor dropout, network partition, delayed evidence, context reset 시험.
  3. 폐루프 task: 합성 state-tracking 점수와 실제 robot/설비 성공률의 상관 및 오류복구 측정.
  4. 장기 실증: 고수준 계획·감시부터 시작하고 저수준 안전제어는 독립 안전 controller와 단계적 검증.
SYNTHESIS새 연구가 보여준 가장 중요한 변화는 “더 적은 토큰” 자체가 아니다. 어떤 정보를 제거했는지와 제거 뒤 어떤 network가 실제로 실행되는지를 함께 증명하기 시작했다는 점이다. 다음 단계는 그 증명을 센서·메모리·에너지·복구까지 확장하는 것이다.
