THE CENTRAL QUESTION

문맥 길이에 독립적인 recurrent state라 해도, 실제로는 왜 수천 토큰의 KV cache만큼 크고 매 decode step의 병목이 될 수 있는가?

2026년 11월 4일 arXiv에 공개된 v1 프리프린트 Shallow Encoding Emits Deep Memories은 하이브리드 언어모델의 메모리를 두 축으로 얕게 만든다. Prefill에서는 깊이를, decode에서는 표현 rank를 줄인다. 저자들은 이를 SEED라 부르며, 30B에서 320B급 다섯 production hybrid의 여섯 checkpoint에 적용했다. 조사 기준일까지 정식 학회·저널 발표나 개정본은 확인되지 않았다.

PART 01 · DEFINITION
01

정의: “고정 상태”와 “작은 상태”는 같은 말이 아니다

LFM은 Liquid AI의 모델군이고, Mamba는 입력 의존 선택성을 가진 상태공간 아키텍처 계열이다. LFM2는 입력 의존 gated short convolution과 일부 GQA를 결합하며, LFM3는 Liquid AI가 2026년 10월 공개한 별도의 tri-hybrid 제품군이다. 따라서 LFM=LTC=LNN=Mamba라는 동일시는 틀리며, SEED의 Mamba-2 결과를 모든 LFM 세대에 소급해서는 안 된다.

Hybrid language model은 소수의 softmax attention 층과 다수의 linear-attention 또는 state-space 층을 섞는다. Attention 층은 토큰별 KV cache를 저장하고, recurrent 층은 head별 고정 크기 행렬 상태를 저장한다. 이 상태의 크기는 문맥 길이에 직접 비례하지 않지만 head 수·층 수·상태 차원·정밀도에는 비례한다.

사실Qwen3.8-Flash-Next에서 저자들이 계산한 한 request의 fp32 recurrent state는 113.2 MB다. 이는 해당 모델의 attention cache 약 4.5K tokens와 같은 규모다. 길이에 독립이라는 말은 정보가 무한히 보존되거나 실제 메모리가 작다는 뜻이 아니다.
PART 02 · PROBLEM FORMULATION
02

문제 정의: 품질·지연·메모리·에너지를 함께 최적화한다

공통 목표는 긴 이력, 낮은 추론 비용, 높은 정확도를 동시에 만족하는 것이다. 실무에서는 품질을 최대화하되 p95 지연, peak memory, 에너지, 처리량을 제약으로 둔다.

maximize Quality(θ) subject to p95 latency ≤ L, peak memory ≤ M, energy/task ≤ E, throughput/GPU ≥ T

표준 full attention의 prefill은 길이에 대해 이차 연산이고, KV cache는 선형으로 증가하며, decode 한 토큰의 attention은 이력 길이에 선형이다. 고정 상태 순수 SSM은 총 선형 연산과 길이에 독립적인 순환 상태를 갖는다. 그러나 hybrid는 두 메모리를 모두 가진다. GQA는 KV 크기의 계수를 줄일 뿐 길이 의존을 제거하지 않는다.

PART 03 · CORE CONCEPTS
03

핵심 개념: 쓰기는 얕고, 읽기는 깊다

Selective SSM과 기억 접근

ht = Ātht−1 + B̄txt,   yt = Ctht

선택성은 입력별 기억·망각·읽기의 조절이며 추론 중 가중치를 학습한다는 뜻이 아니다. Mamba-2는 state-space duality 관점에서 head별 matrix state를 쓰고 읽는다. SEED는 이 recurrence를 새 것으로 바꾸지 않고, 이미 학습된 상태가 실제로 어떤 구조를 갖는지 측정한다.

Write–read asymmetry

한 토큰이 깊은 층의 memory에 무엇을 쓸지는 그 층으로 들어오는 residual stream과 write path로 정해진다. 반면 다음 토큰을 읽어 예측하려면 deep attention·recurrent read·FFN을 모두 통과해야 한다. 저자들은 5개 모델에서 anchor depth가 전체의 63–89%에 놓이더라도 deep write를 복원할 수 있음을 관찰했다. Prompt의 마지막 토큰과 모든 생성 토큰은 원래처럼 모든 층을 통과한다.

State sink와 working memory

S = a v̄T + UVT

저자 정의에서 a v̄ᵀ는 head별 고정 방향을 따르는 rank-one state sink이고, UVᵀ는 prompt-dependent content다. 다섯 모델에서 sink는 head를 합쳐 state energy의 69–99.7%를 담았다. 그러나 에너지가 크다는 것과 정보가 많다는 것은 다르다. Sink는 normalization 뒤 bias와 gain처럼 작동하고, prompt-specific read content는 비교적 짧은 저랭크 working memory에 놓인다.

해석연구 흐름은 “더 효율적인 연산자”에서 “어떤 상태가 실제 정보를 담고, 어떤 바이트가 서비스 병목을 만드는가”로 이동한다. 이는 기억 회수·상태 추적·하드웨어 공동설계를 하나의 계측 문제로 묶는다.
PART 04 · INTRODUCTION
04

도입: 두 병목을 한 번에 줄이는 SEED

SEED는 Shallow Encoding Emits Deep Memories의 약자다. Prefill에서는 shallow-in-depth, decode에서는 shallow-in-representation이라는 서로 다른 인코딩을 사용한다.

  1. Prefill: 마지막 토큰을 제외한 N−1개 prompt token은 anchor layer까지만 계산한다. 학습된 emitter는 그 residual에서 더 깊은 attention cache와 recurrent state를 작성한다.
  2. Decode: state sink는 정확히 보존하고, content는 rank-R factors로 저장한다. 매 step의 갱신은 factor column을 하나 추가하는 정확한 update이고, W step마다 rank-R로 다시 압축할 때만 근사가 생긴다.
  3. 보존: 원 모델의 weight는 frozen이며 attention KV cache는 압축하지 않는다. 마지막 prompt token과 모든 생성 token은 전체 L개 층을 실행한다.

SEED의 핵심 기여는 prefill FLOPs 절감과 decode state 절감을 같은 “압축”으로 뭉개지 않고, 각 phase의 다른 병목에 맞춘 두 방법으로 분리한 것이다.

PART 05 · MOTIVATION & BACKGROUND
05

필요성과 배경: O(1)이라는 표기 뒤의 113 MB

긴 문맥에서 KV cache가 커지는 문제는 잘 알려져 있다. 반면 recurrent state는 길이에 독립이라는 이유로 종종 “상수이므로 작다”고 취급된다. 하지만 production hybrid는 수십 층, 다수 head, fp32 state를 가지며 매 decode step 전체 상태를 읽고 다시 쓴다. HBM capacity는 batch와 prefix cache를 제한하고, HBM traffic은 step time에 직접 들어간다.

Prefill bottleneck

긴 agentic prompt에서는 N−1개 토큰이 다음 토큰을 직접 예측하지 않고 deep memory를 쓰기 위해 전체 층을 통과한다. 저자들은 이 write path가 read path보다 얕다고 본다.

Decode bottleneck

Qwen3.8-Flash-Next의 recurrent state는 request당 113.2 MB다. 작은 batch에서는 weight가 bytes를 지배하지만 높은 concurrency에서는 state pool이 capacity를 제한한다.

Prefix-cache pressure

SGLang hybrid serving에서 cached prefix도 recurrent-state pool의 slot을 차지한다. 상태가 작아지면 running request와 cached prefix를 더 많이 유지할 수 있다.

Frozen checkpoint

SEED는 base weight를 바꾸지 않고 emitter와 prompt code만 학습한다. 이는 새 아키텍처 사전학습보다 도입 위험을 낮추지만 checkpoint별 calibration은 남는다.

LFM2의 hardware-in-the-loop 설계, Mamba-3의 이산화·복소수 상태·MIMO, Samba의 SSM+sliding-window attention은 서로 다른 문제를 푼다. SEED는 그 위에서 serving memory representation을 후처리하는 방법이다.

PART 08 · APPROACHES / METHODS
08

접근법: emitter, sink 분해, 주기적 압축, 실제 serving

1. Shallow prefill

저자들은 각 checkpoint에서 untrained probe로 anchor depth를 선택한다. Qwen3.8-Flash-Next는 48층 중 31층, Nemotron-3.5-Lightning은 52층 중 33층, Kimi-Linear는 27층 중 19층, GLM-5.3-Flash는 45층 중 31층, Nemotron-3.5-Super는 88층 중 78층까지 prompt token을 실행한다. Qwen3.8-Flash-Next의 prompt parameter FLOPs는 저자 계산으로 token당 12.1에서 9.1 GFLOP으로 줄었다.

2. Exact factored update

Sink의 평균 방향은 request 간 공유하고, request별로 coefficient a와 factors U,V를 저장한다. Mamba-2, Gated DeltaNet, Kimi Delta Attention의 update는 factor에 새 column을 추가하는 형태로 정확히 확장된다. 근사는 오직 매 W step의 rank truncation에서 생긴다. 저자 설정은 모델에 따라 R=W=16 또는 R=W=32다.

3. Accuracy protocol

여섯 component set을 원 모델과 같은 질문·request seed로 비교했다. GPQA-Diamond, AIME 2024+25, MATH-500, MMLU, IFEval, LiveCodeBench v6, HumanEval+, LongBench v2, RULER 32K/64K/128K 등 11개 시험을 사용했다. 66개 checkpoint–exam cell 중 63개가 원 모델 대비 2 standard errors 안이거나 그 이상이었다는 것이 저자 결론이다.

4. Serving protocol

SGLang과 NVIDIA GB300 GPU에서 agentic-coding trace를 replay했다. 각 measurement는 900초 단일 run이며 SEED 자체 emitter·compression 비용을 포함한다. Qwen3.8-Flash-Next에서 aggregated NVFP4 TP1, aggregated bf16 TP2, disaggregated bf16 1P:1D를 비교했다.

PART 09 · KEY APPLICATIONS
09

핵심 활용: 긴 프롬프트와 많은 동시 요청이 만나는 곳

Agentic coding

긴 repository context와 tool history가 prefill을 지배하고 다수 session이 state pool을 압박한다. 논문의 직접 serving 실험 영역이다.

Local RAG

Evidence chunk가 길고 반복 prefix가 많은 환경에서 shallow prefill과 더 높은 prefix-cache hit가 결합될 수 있다. 근거 회수율은 별도 검증해야 한다.

Streaming assistant

온디바이스 text·speech·vision assistant에서 고정 state는 유리하지만 state precision과 energy를 함께 측정해야 한다. 이 논문은 GB300 결과만 제공한다.

Hybrid model serving

Gated DeltaNet, KDA, Mamba-2를 attention과 섞은 모델에서 state pool과 KV cache를 서로 다른 정책으로 운영할 수 있다.

ETRI 연구 제안

센서 상태 추적·로봇 고수준 계획·edge 운영지능에서 compressed state + 필요한 구간 attention + 외부 evidence memory의 3계층 구조를 시험한다.

안전 경계

저수준 제어의 안정성은 별도 검증 대상이다. State compression의 language-model drift 결과가 actuator safety를 보장하지 않는다.

PART 10 · OPEN PROBLEMS
10

미해결 문제: 압축 가능한 상태와 신뢰 가능한 상태 사이

  • 유한 상태의 과제별 한계: rank-R working memory가 exact retrieval, state tracking, planning에 필요한 최소 정보량을 언제 넘지 못하는가?
  • 망각 탐지: next-token KL이 작아도 특정 evidence key가 지워졌는지 online으로 감지할 방법이 필요하다.
  • 장기 session drift/reset: 16K보다 긴 decode, tool loop, state contamination, session reset에서의 안정성은 미확인이다.
  • 공정 비교: 동일 checkpoint·prompt trace·precision·batch·hardware에서 dense state, quantization, pruning, low rank, offload를 비교해야 한다.
  • 효과 분리: emitter training data, anchor depth, prompt code, rank, W, prefix-cache hit가 throughput과 품질에 미치는 영향을 분리해야 한다.
  • 실세계 안전성: exam cell 63/66은 강한 paired evidence지만 잘못된 tool call, hallucinated evidence, recovery failure를 직접 측정하지 않는다.
  • 한국어 전문업무: 한국어 장문 RAG, 연구·행정 문서, 현장 terminology에서 근거 회수율과 압축 drift가 검증되지 않았다.
  • LFM 검증: LFM2·LFM3 전체가 Mamba-2와 같은 state update를 쓴다는 공개 근거가 없으므로 method transfer는 가설로 남는다.
PART 11 · FUTURE DIRECTIONS
11

향후 방향: 상태 예산을 고정값이 아니라 운영 변수로 만든다

1. Hierarchical memory

제안압축 recurrent state + 필요한 구간의 attention + 외부 evidence memory를 계층화한다. State는 최근 동적 문맥, attention은 선택된 정확 회수 구간, 외부 memory는 감사 가능한 근거를 담당한다.

2. Adaptive state budget

제안항상 같은 R과 W를 쓰지 말고 retrieval uncertainty, state novelty, tool boundary, safety-critical step에서 rank를 늘린다. 평상시에는 작게 유지하고 필요한 순간에만 memory budget을 확장한다.

3. Task-success benchmark

제안Perplexity와 tok/s만으로 끝내지 않는다. 성공 작업당 Joule, p95 TTFT, peak HBM, 근거 회수율, 오류 복구율, state reset 후 회복 시간, 장기 session drift를 함께 보고한다.

4. ETRI용 단계적 검증

단계실험통과 기준 예시상태
1 · 통제 비교동일 학습데이터·checkpoint·quantization·hardware에서 dense vs low-rank품질 비열화 한도와 memory/latency 동시 개선연구 제안
2 · 고장 주입state contamination, evidence deletion, 통신 단절, reset오류 탐지율·회복률·최악 지연연구 제안
3 · 장기 실증로봇·설비의 고수준 계획과 edge 운영지능성공 작업당 Joule·근거 회수·안전 handoff연구 제안
4 · 저수준 제어별도 control-theoretic safety 검증stability margin·fail-safe·independent monitor분리 과제
종합 제안SEED가 제시한 가장 중요한 변화는 “고정 상태”를 아키텍처 속성이 아니라 관찰·압축·확장·복구할 수 있는 시스템 자원으로 보는 것이다. 다음 연구는 state rank를 줄이는 데서 멈추지 말고, 어떤 task evidence가 사라졌는지 설명하고 필요할 때 budget을 되돌릴 수 있어야 한다.
