한 개의 확률 비트로 17억 개 파라미터를 모두 표현했다는 결과는 곧바로 메모리·지연·에너지 우월성을 뜻하는가?

아니다. 새로 확인된 PBit1은 LFM3-1.7B의 모든 학습 스칼라를 유한 제어 확률 표현으로 변환하고, 다섯 개 독립 가중치 draw에서 사전 고정한 품질 기준을 충족한 중요한 완전 모델 검증이다. 그러나 완전 모델 계산은 복원한 BF16 가중치를 재사용하는 R1 체제이고, 실제 확률 하드웨어의 native full-model 실행이 아니다. 이 글은 그 성과를 보존하면서도 비용·에너지 주장의 경계를 분명히 한다.

PART 01 · DEFINITION
01

Definition

Liquid Foundation Models(LFM)은 Liquid AI가 공개하는 모델군의 이름이다. Mamba는 입력별로 상태 전이·쓰기·읽기를 조절하는 선택적 상태공간 아키텍처 계열이다. LFM=LTC=LNN=Mamba라는 동일시는 틀리다. LFM2의 입력 의존 gated short convolution과 일부 GQA 구조를 LFM3에 소급해서도 안 된다.

LFM3-1.7B는 공식 모델카드 기준 24층 tri-hybrid 텍스트 모델이다. 13개 gated short convolution, 5개 256-token sliding-window attention, 6개 global attention 층을 사용한다. 이는 공식 제품·모델 정보이며 peer-reviewed 논문과 구분한다.

PBit1은 사전학습된 각 스칼라 파라미터에 하나의 논리적 programmable probabilistic bit(p-bit)를 대응시키는 유한 제어 표현이다. 순간 상태는 이진이지만 stationary probability를 조절하고 반복 관측한 평균으로 연속 가중치를 복원한다. 따라서 “한 p-bit”는 “가중치가 0 또는 1만 갖는다”거나 “한 비트 저장만 필요하다”는 뜻이 아니다.

SCOPEPBit1은 LFM3-1.7B의 가중치 표현을 검증했다. LFM3의 tri-hybrid 연산자를 바꾸거나 Mamba의 순환 상태를 확률 비트로 구현한 논문이 아니다. 이번 결과를 Mamba-3의 상태 안정성 또는 모든 LFM 세대의 효율성으로 확장할 수 없다.
PART 02 · PROBLEM DEFINITION
02

Problem Definition

LFM·Mamba 계열의 공통 시스템 문제는 긴 이력에서도 높은 정확도를 유지하면서 p95 지연, 피크 메모리, 에너지를 제한하는 다목적 설계다. PBit1은 여기에 새로운 축을 더한다. 파라미터마다 stochastic element를 하나만 배치할 때, 유한한 제어 필드와 시간 관측만으로 사전학습 함수가 얼마나 잘 보존되는가?

maximize Task Quality   subject to   p95 Latency ≤ L, Peak Memory ≤ M, Joule/Task ≤ E, Spatial Elements ≤ S, Observations ≤ T

이 문제에서 저장비용·복원시간·실행비용은 분리해야 한다. 명령과 범위를 저장하는 비용, p-bit 상태를 읽는 비용, 가중치를 복원하는 비용, 복원한 가중치로 추론하는 비용이 서로 다르기 때문이다. 한 항목만 줄어도 전체 시스템의 Pareto frontier가 개선된다고 단정할 수 없다.

INTERPRETATIONPBit1의 핵심 성과는 “1-bit LFM3”가 아니라, 공간의 stochastic element 수와 시간에 따른 추정 정밀도를 분리한 완전 모델 표현을 실제 체크포인트에서 검증했다는 점이다.
PART 03 · CORE CONCEPTS
03

Core Concepts

유한 명령과 시간 관측

그룹 g의 최소값과 범위를 각각 lg, dg라 하고, 확률 명령이 만드는 programmed probability를 p̃i라 하면 복원값은 다음과 같다.

zi(t) ~ Bernoulli(p̃i),   ni = Σt=1T zi(t),   ŵi,T = lg + dg ni/T

12-bit 명령 qi는 0–4095의 유한 격자다. T를 늘리면 p̃ 주위의 sampling variance는 줄지만, 유한 명령과 공유 범위가 만든 encoding bias는 사라지지 않는다. 논문이 직접 decoding한 controller mean과 sampled reconstruction을 따로 보고한 이유다.

R1과 R2

R1 · Reconstruct then infer

샘플로 가중치를 한 번 복원한 뒤 BF16 추론에 재사용한다. 세 완전 모델 결과는 모두 R1이다.

R2 · Accumulate outputs

샘플 가중치가 만든 선형 연산 출력을 시간축으로 누적한다. THRML operator test에서만 다룬다.

Spatial budget

스칼라당 stochastic element 수. K1은 하나, K4는 네 개를 사용한다.

Temporal budget

관측 횟수 T. 정밀도는 대략 T의 제곱근에 따라 개선되므로 한 비트의 공간 표현이 고정 정밀도를 뜻하지 않는다.

Mamba의 상태와 구분

Mamba의 선택적 SSM은 h_t=Ā_t h_(t−1)+B̄_t x_t, y_t=C_t h_t로 요약된다. 선택성은 입력별 기억·망각·읽기의 조절이지 추론 중 가중치 학습이 아니다. 순환 상태 크기가 길이에 독립해도 무한 정보를 완전 보존한다는 뜻은 아니다. PBit1은 이 activation state가 아니라 학습된 parameter state를 표현한다.

표준 full attention은 prefill에서 길이에 대해 이차 연산, KV cache에서 선형 메모리, decode 한 토큰에서 이력 길이에 선형인 attention 비용을 갖는다. 순수 고정 상태 SSM은 총 선형 연산과 길이에 독립적인 순환 상태를 가질 수 있다. 그러나 LFM3는 convolution·SWA·global attention 혼합이므로 전체를 O(1) 메모리나 완전 선형이라고 부를 수 없다.

PART 04 · INTRODUCTION
04

Introduction

PBit1: One Programmable P-Bit per Parameter은 arXiv v1이 2026년 11월 14일 UTC 제출되었고 공개 목록에서 11월 17일 확인된 7쪽 본문·12쪽 부록의 프리프린트다. 실행일 현재 정식 학회·저널 발표 기록은 확인되지 않았다. 저자는 GPT-2, SST-2 fine-tuned DistilBERT, LFM3-1.7B의 모든 학습 스칼라—bias와 normalization parameter 포함—를 변환하고, tied embedding과 output head는 하나의 공유 표현으로 계산했다.

LFM3 실험은 WikiText-2의 62개 article, 607개 window, 294,442개 scored token을 사용한다. BF16 가중치·연산의 결정적 reference와 다섯 개 독립 가중치 draw를 비교했고, 로컬 NVIDIA DGX Spark/GB10에서 CPU master weight와 GPU offloading으로 실행했다.

FACT선정된 LFM3 배치에서 BF16 perplexity는 18.93015, sampled K1은 18.97918이었다. log-loss 공간 비율은 1.00259, 조건부 Monte Carlo 95% t 구간은 [0.98751, 1.01790]로, 사전 정의한 상한 1.02 기준을 충족했다.
LIMIT이 구간은 고정 데이터와 다섯 seed의 reconstruction variability를 기술한다. 데이터 표본, 다른 과제, 장문 생성, instruction following, 장기 세션 전체에 대한 보편적 비열등성 구간이 아니다.
PART 05 · MOTIVATION AND BACKGROUND
05

Motivation and Background

2025–2026년 LFM·Mamba 연구 흐름은 단순히 효율적인 operator를 찾는 단계에서 memory fidelity, state tracking, low-precision stability, hardware co-design으로 이동했다. LFM2는 hardware-in-the-loop 탐색, gated short convolution, 일부 GQA, Top-K distillation과 curriculum을 결합했다. LFM3는 별도 세대로 24층 tri-hybrid와 22T-token training recipe를 공식 공개했다. Mamba-3는 exponential-trapezoidal discretization, complex state, MIMO로 상태 추적과 decode 효율을 함께 노렸다.

PBit1은 이 흐름의 parameter representation 측면을 보완한다. 기존 post-training quantization이 고정된 몇 비트의 code와 scale을 중심으로 한다면, PBit1은 하나의 stochastic element, 12-bit probability control, shared affine range, temporal observations를 결합한다. 같은 공간 element 수에서도 더 많은 시간을 쓰면 추정 variance를 줄일 수 있다는 설계다.

INTERPRETATION연구의 무게중심은 “어떤 operator가 이론적으로 선형인가”에서 “가중치·순환 상태·외부 메모리를 어떤 정밀도와 시간 예산으로 보존하고, 실제 하드웨어에서 얼마의 지연·에너지로 회수하는가”로 확장되고 있다.

PART 08 · APPROACHES
08

Approaches (Methods)

PBit1: range와 observation을 분리한다

방법은 먼저 operator별 weight layout을 고르고, 선택 방향으로 행렬을 평탄화한 뒤 128개 연속 원소를 한 그룹으로 묶는다. LFM3 depthwise convolution filter는 7개, normalization tensor는 16개 그룹을 사용한다. 각 그룹의 min/span을 FP32로 저장하고 각 스칼라를 12-bit probability field로 encoding한다.

complete-model protocol은 다섯 seed, T=32,768을 사전 고정한다. BF16 reference의 mean NLL ℓ0와 각 sampled model의 ℓs 차이 ds를 구하고, perplexity ratio를 exp(mean d)로 계산한다. 사전 기준은 조건부 95% 구간 상단이 1.02 이하인 것이다.

K1과 K4: “동일 관측”도 회계가 다르다

THRML operator 실험에서 8×768 GPT-2 output-head bank를 비교했다. K1은 6,144 element와 T=32,768로 mean MSE 7.0041×10−5, K4는 24,576 element와 T=8,192로 같은 scheduled all-node observations에서 3.3115×10−6을 보였다. 그러나 K4의 세 coarse node는 clamped이므로 free stochastic update 수가 다르다. 단일 “observation count”만으로 에너지 등가를 주장할 수 없다.

device mismatch: 이상적 샘플링과 물리 장치의 간극

GPT-2의 1,024 training target 시뮬레이션에서 gain·offset mismatch는 ideal reconstruction 대비 paired PPL ratio 1.03229 [1.00038, 1.06522]를 만들었다. oracle correction은 mean squared bias를 약 447배 줄였지만, 파라미터마다 FP32 calibration 값 두 개를 저장하면 약 996MB가 추가된다.

LIMIT초록의 “sensitivity policy가 observation을 41.7% 줄였다”는 결과는 GPT-2에 대한 것이다. LFM3에서도 동일 절감이 검증된 것처럼 쓰면 안 된다.

기존 LFM·Mamba 방법과의 연결

LFM2/LFM3의 hardware-in-the-loop architecture search는 어떤 layer mix가 실제 backend에서 유리한지 찾는다. PBit1은 이미 학습된 checkpoint의 parameter representation을 바꾼다. Mamba-3는 discretization·complex state·MIMO로 recurrence의 표현력을 바꾼다. 세 접근은 architecture, representation, state dynamics라는 서로 다른 층위이며, 어느 하나의 결과를 다른 층위의 성능 원인으로 환원할 수 없다.

PART 09 · KEY APPLICATIONS
09

Key Applications

온디바이스 LFM

공간 element가 제한된 장치에서 parameter representation과 관측시간을 교환할 수 있는지 연구하는 출발점. 실제 제품 적용에는 physical device 검증이 필요하다.

로컬 RAG·에이전트

복원 모델의 perplexity뿐 아니라 근거 회수율, tool-call 정확도, 장기 session drift를 함께 측정한다.

스트리밍 분석

R1의 일회 복원과 R2의 지속 누적을 비교해 latency spike, recalibration, drift를 관리한다.

Physical AI

로봇 고수준 계획·센서 상태 추적·엣지 운영지능에서 model weight와 recurrent state를 서로 다른 정밀도 예산으로 운영할 수 있다.

PROPOSALETRI 온디바이스 협업지능 실증에서는 동일 checkpoint·학습데이터·quantization·hardware에서 BF16, optimized PTQ, PBit1-R1, native R2 후보를 비교하고 성공 작업당 Joule·p95 지연·피크 host/GPU/NPU 메모리·근거 회수율·오류 복구율을 동시에 기록한다. 이는 논문 결과가 아니라 연구 제안이다.

저수준 로봇 제어와 기능 안전은 별도 검증 대상이다. 확률 장치의 drift나 긴 calibration interval이 안전 임계값을 넘을 수 있으므로, 고수준 planner의 평균 품질만으로 actuator-level 사용을 정당화할 수 없다.

PART 10 · OPEN PROBLEMS
10

Open Problems

  • 과제별 유한 기억 한계: weight reconstruction fidelity가 context memory와 state-tracking 능력을 얼마나 보존하는지 분리해야 한다.
  • 망각·drift 탐지: physical p-bit의 correlation, retention, temperature drift를 online health signal로 탐지할 방법이 필요하다.
  • 장기 session reset: parameter drift, Mamba recurrent state contamination, external memory corruption을 서로 다른 reset 주기로 관리해야 한다.
  • 재현 가능한 공정 비교: packed representation의 이론 bit 수와 current uint16 implementation, reconstructed BF16 copy를 구분해 보고해야 한다.
  • 실세계 안전성: physical device fault와 calibration failure가 abstention·fallback·human handoff에 어떻게 연결되는지 검증되지 않았다.
  • 한국어 전문업무: WikiText-2 perplexity 보존만으로 한국어 정책문서, 연구기획, 로봇 안전 판단의 기능 보존을 알 수 없다.
  • Mamba 직접 검증 부재: recurrent state와 complex dynamics를 가진 Mamba-3에 PBit1을 적용한 결과는 없다.
REPRODUCIBILITY저자는 saved-output rescoring, 별도 SDK, prespecified replay가 기록된 runtime에서 bitwise 일치한다고 보고하고 code·research archive를 공개했다. 완전 재현에는 별도로 저장된 checkpoint와 array가 필요하며, 독립 재현 결과는 아직 확인되지 않았다.
PART 11 · FUTURE DIRECTIONS
11

Future Directions

1. 계층형 메모리와 계층형 정밀도

압축 순환 상태, 필요한 구간만의 attention, 외부 evidence memory에 더해 parameter representation의 시간 예산을 계층화한다. 항상 같은 T를 쓰지 않고, uncertainty·state drift·task criticality에 따라 관측 예산을 늘리는 적응형 정책이 필요하다.

2. 필요한 때만 기억·정밀도 예산을 확장

평상시에는 낮은 observation budget과 압축 state를 쓰고, 충돌 증거·안전 임계값·장기 회수 요청이 나타나면 weight readout, recurrent state precision, evidence retrieval을 동시에 확장하는 구조를 제안한다.

3. 성공 작업당 시스템 벤치마크

token/s나 perplexity만으로는 부족하다. 성공 작업당 Joule, p95 latency, end-to-end peak memory, evidence recall, semantic flip, error recovery, recalibration interval을 하나의 공개 protocol로 묶어야 한다. CPU/GPU/NPU/확률 가속기에서 kernel과 data movement까지 포함한다.

4. ETRI 단계적 검증

  1. 단계 A · 소프트웨어 재현: 공개 LFM3-1.7B와 PBit1 snapshot으로 BF16/controller-mean/five-draw 결과를 재현한다.
  2. 단계 B · 공정 비교: 동일 데이터·quantization·hardware에서 AWQ/GPTQ/PBit1-R1을 비교한다.
  3. 단계 C · 상태 결합: Mamba-2/3 또는 hybrid model에서 weight reconstruction과 recurrent state precision을 독립 조작한다.
  4. 단계 D · 장애 시험: state contamination, correlated sampling, device drift, 통신 단절, calibration loss를 주입한다.
  5. 단계 E · 장기 실증: 로봇·설비의 고수준 계획과 edge operations에서 주 단위 drift/reset/recovery를 검증한다.
PROPOSAL미래의 효율 모델은 “파라미터 수가 적다”가 아니라, 필요한 순간에 필요한 기억과 정밀도를 필요한 에너지로 복원하는 시스템이어야 한다. PBit1은 이 명제를 완전 모델 수준에서 시험할 수 있는 유용한 출발점이지만, 완성된 하드웨어 결론은 아니다.
