T01 · 협업·팀 구성: 역할보다 작동하는 조정

기존 판단: 유지·구체화 · 추가 근거: P27

1. Definition

작업 정의: 팀 구성은 역할 이름을 붙이는 일을 넘어, 요청·수락·결정·통합의 책임을 정하는 과정이다. 이 절의 설명은 시스템 설계를 위한 분석 틀이며 새로운 실험 결과가 아니다.

2. Problem Definition

보고서 초안을 여러 에이전트가 나눠 작성해도 최종 용어와 출처가 맞지 않으면 공동 산출물은 실패한다. 누가 충돌을 해결하고 언제 합의를 확정하는지를 과업 명세에 포함해야 한다.

3. Core Concepts

요청의 수신자, 실행을 시작시키는 메시지, 구속력 있는 결정, 통합 완료를 구분한다. 대화 횟수가 많다는 사실만으로 조정이 성공했다고 판정하지 않는다.

4. Introduction

근거 추가: P27은 메시지 프로토콜을 팀 운영의 설계 대상으로 다룬다. 기존 T01의 상보성 중심 설명에 조정 규칙의 실행 여부를 묻는 관점을 더한다.

5. Motivation and Background

해석: 구성원의 능력이 같아도 요청 처리 규칙이 다르면 중복 작업이나 무응답이 생길 수 있다. 모델 선정과 운영 규칙을 서로 다른 실험 요인으로 취급할 이유다.

6. Challenges

제안 설계의 난점: 역할·도구·동시성·정보량을 함께 바꾸면 어떤 변화가 결과를 만들었는지 알기 어렵다. 단순 팀과 복잡한 팀을 같은 비용 예산에서 비교해야 한다.

7. Research Questions

문헌의 탐구 대상은 메시지를 통한 조정과 책임 추적이다. 추가 질문은 “역할 프롬프트가 같을 때 실행 가능한 수락 규칙만으로 통합 실패를 줄일 수 있는가”이다.

8. Approaches (Methods)

근거: P27의 운영 실험 조건과 보정 통계는 아래 근거표에서 확인한다. 제안: 새 비교에서는 메시지 시작 규칙과 반복 제한을 분리한 요인설계를 사용한다.

9. Key Applications

확장 제안: 연구기획의 근거 수집·작성·검토 역할에 적용할 수 있다. 승인 요청이 실제 공개로 연결되는 단계는 역할 간 합의와 별도로 검증한다.

10. Open Problems

미해결: 팀 내 합의가 사실의 정확성까지 보장하지는 않는다. 잘못된 출처에 만장일치하는 실패를 통합 성공과 구분할 평가가 필요하다.

11. Future Directions

제안: 동일 과업에서 단독 실행·단순 메시지 팀·규칙 강제 팀을 비교한다. 최종 품질이 같아도 사람의 검토시간이 늘면 실무 우위 주장은 보류한다.

직접 근거: P27 §5;§6.2–6.4;§7;§10;Appendix C.2

T02 · 주도권·위임: 개입 가능한 실행 경계

기존 판단: 유지·구체화 · 추가 근거: P27·P28

1. Definition

작업 정의: 실효 통제는 원하지 않는 행동을 제때 막거나 수정할 수 있는 능력이다. 화면에 중단 버튼이 있다는 사실과 행동 전에 사용할 수 있다는 사실은 다르다.

2. Problem Definition

사용자가 오류를 발견했을 때 이전 상태로 돌아갈 수 있는가가 문제다. 문서 편집의 복구와 외부 전송의 복구를 같은 되돌리기로 취급해서는 안 된다.

3. Core Concepts

관찰, 진단, 분기, 재실행, 외부 효과를 분리한다. 실행 기록의 가시성은 개입을 위한 입력이며 권한 경계의 강제는 별도 기능이다.

4. Introduction

근거: P28은 실행 추적에서 과거 단계로 분기하는 개입을 구현했다. P27의 메시지 규칙과 함께 보면 계획 설명과 실행 제어를 서로 다른 층으로 분석할 수 있다.

5. Motivation and Background

해석: 최종 결과만 고치면 어느 결정이 잘못됐는지 학습하기 어렵다. 반면 모든 중간 단계에 확인을 요구하면 감독 부담이 커질 수 있으므로 확인 위치도 연구 대상이다.

6. Challenges

제안 설계의 난점: 파일 상태를 복구해도 이미 보낸 메시지나 외부 변경은 남을 수 있다. 되돌릴 수 있는 상태와 보상 조치가 필요한 상태를 표시해야 한다.

7. Research Questions

추가 질문: 오류 발생 후 복구시간보다 오류 발생 전 적시 차단을 더 잘 지원하는 경계는 무엇인가. 통제감과 실제 차단 성공률의 차이도 독립적으로 측정한다.

8. Approaches (Methods)

근거 범위: P28의 분기 기능은 코딩 환경에서 확인했다. 제안: 공개·삭제·전송은 실제 외부 도구 대신 모의 환경에서 오류를 주입하고 복구 가능성을 시험한다.

9. Key Applications

확장 제안: 문헌검토 초안에서 승인된 문장만 게시하는 워크플로에 연결한다. 초안 수정 권한과 공개 권한을 분리한 정책이 실제로 실행되는지 확인한다.

10. Open Problems

미해결: 분기 후 여러 산출물의 권한과 출처가 충돌할 수 있다. 과거 승인이 수정된 결과에도 유효한지 판단할 의미론이 필요하다.

11. Future Directions

제안: 동일 확인 횟수 아래 고정 주기와 영향 기반 확인을 비교한다. 경계 위반 감소의 신뢰구간이 최소 의미 효과를 지지하지 않으면 설계 우위를 선언하지 않는다.

직접 근거: P27 §5;§6.2–6.4;§7;§10;Appendix C.2, P28 §III-A;§V-A Table I;§V-B Fig.6;§V-C;§VI

T03 · 신뢰·의존·아첨: 선호와 결과를 분리

기존 판단: 유지·근거 확장 · 추가 근거: P29

1. Definition

작업 정의: 아첨은 사용자의 견해를 근거 없이 지지하는 반응이다. 친절한 표현 자체와 구분하고, 사용자가 느끼는 이해와 조언의 타당성을 따로 평가한다.

2. Problem Definition

질문은 “좋아하는 AI가 좋은 영향을 주는가”이다. 만족도 하나로 신뢰의 적절성을 평가하면 사용자가 원하는 긍정과 실제 도움이 섞인다.

3. Core Concepts

정서적 지지, 인정, 정보적 도움, 조언 선호는 다른 구성개념이다. 본 글의 해석에서는 이 변수들을 단일 신뢰 점수로 환산하지 않는다.

4. Introduction

근거 추가: P29는 아첨형·중립형·도전형 반응을 비교했다. P12의 단회 실험과 합쳐 하나의 표본으로 계산하지 않고 독립 연구로 등록한다.

5. Motivation and Background

해석: 사용자가 다시 쓰겠다고 답하더라도 잘못된 판단을 바로잡는 데 도움이 되었는지는 별도 질문이다. 제품 평가에서 재사용 의도와 판단의 질을 분리할 필요가 있다.

6. Challenges

제안 설계의 난점: 무조건 반대하는 AI는 아첨의 좋은 대안이 아닐 수 있다. 사실 정보와 어조를 통제하면서 동의의 근거만 조작해야 한다.

7. Research Questions

추가 질문: 사용자 감정을 인정하면서도 문제의 전제를 검토하도록 돕는 반응은 중립형보다 유용한가. 불쾌감 감소와 자기 수정 행동 증가가 함께 나타나는지도 묻는다.

8. Approaches (Methods)

근거: P29의 조작은 적극적 지지와 중립적 관점 제시를 구분한다. 연구 전체 규모와 종단 부분의 표본은 근거표에 따로 제시한다.

9. Key Applications

확장 제안: 기술기획 검토 AI가 제안자의 의도를 존중하면서 반례를 요청하는 인터페이스를 시험한다. 이는 논문에서 검증된 업무 응용이 아니다.

10. Open Problems

미해결: 근거가 충분한 동의와 아첨의 자동 구분이 어렵다. 모델 평가용 합성 대화와 실제 사용자의 목표가 다른 경우를 특히 점검해야 한다.

11. Future Directions

제안: 선호·오류 수정·근거 확인 행동을 공동 보고한다. 선호만 상승하고 오류 수정이 개선되지 않으면 신뢰 조절 개선이라는 해석을 기각한다.

직접 근거: P29 §1;§2 Fig.3;Methods Study4

T04 · 설명·편집: 추론 서술에서 실행 증거로

기존 판단: 유지·구체화 · 추가 근거: P28

1. Definition

작업 정의: 실행 설명은 실제 도구 호출과 상태 변화의 연결을 설명하는 것이다. 모델이 생성한 사고 서술의 충실성과 같은 개념이 아니다.

2. Problem Definition

오류가 생긴 코딩 작업을 검토할 때 긴 로그에서 원인을 찾고 필요한 지점만 수정할 수 있는가가 문제다. 결과물 재작성과 과정 개입을 구분한다.

3. Core Concepts

추적 단위, 상태 스냅샷, 분기, 사람의 수정 이유가 핵심이다. 시각화의 이해도와 수정 후 결과의 정확도는 각각 평가해야 한다.

4. Introduction

근거 추가: P28의 VibeTrace는 관찰·이해·개입·경험 재사용을 연결한다. 기존 T04의 편집 가능성 논지를 실행 이력 인터페이스로 확장한다.

5. Motivation and Background

해석: 설명이 유용하려면 사용자가 다음 행동을 선택하는 데 필요한 정보를 제공해야 한다. 아름다운 그래프보다 오류 지점의 증거와 수정의 영향 범위가 중요하다.

6. Challenges

제안 설계의 난점: 기록의 누락을 그래프가 감출 수 있고, 에이전트 요약이 도구 결과와 다를 수 있다. 출처 없는 원인 설명을 관측된 인과관계로 표시해서는 안 된다.

7. Research Questions

추가 질문: 시간순 로그와 의존관계 그래프의 차이는 정보량을 맞춰도 남는가. 사용자 숙련도가 낮을 때 과신이나 인지 부담이 증가하는지도 검토한다.

8. Approaches (Methods)

T07 · HAIS·운영 보장: 기록과 강제의 다른 역할

우선순위는 R2+의 오프라인 스키마 검증, 다음 R1+의 사용자 실험이다. R5+는 반복 참여와 개인정보 관리 부담 때문에 후속으로 둔다. 대상은 AI 경험이 다른 성인 연구자·지식근로자로 제안한다. 표본은 임의 고정하지 않고 파일럿 분산·최소 의미 효과·과업 내 상관·탈락을 반영한 검정력 분석으로 정한다. 실제 모집 전 동의·보상·중단권·필요한 기관 심의를 갖추고 민감 원문 대신 최소 이벤트를 수집한다. 이번에 사람 모집·구현·실험은 수행하지 않았다.

가설: R2+의 계보는 같은 정보량의 평면 기록보다 원인 복원을 높이고, R1+는 같은 확인 예산에서 경계 위반을 줄인다. R5+의 목표는 기억의 유용성을 유지하면서 오래된 선호의 오적용을 줄이는 것이다. 결과를 보기 전에 허용 시간·최소 효과·제외·결측·다중비교 규칙을 고정한다.

PART 05 · 확인 범위와 남은 공백

arXiv·공식 출판사·저자기관을 우선하여 서지와 본문을 확인했다. P27–P29는 방법·결과를 확인했고, 초기26편 전체를 오늘 다시 전문 검토하지는 않았다. P03·P05는 v1 서지를 재확인했으며 P02 직접 랜딩 접근은 실패해 철회·최신 버전 확인을 완료했다고 주장하지 않는다. P12 출판사 본문은 접근 제한이 있어 구조화 초록 범위다. P24는 v2와 출판사 초록, P19는 출판사 방법 절을 확인했다.

추가 후보에는 Principled Human-AI Collaboration in Agentic Workflows(arXiv:2611.01566), 웨어러블 상호작용(2611.04692), 문화·인지 통합 서베이(2606.08274), XR 적응 인터페이스(2609.31138)가 있다. 초록 또는 검색 발견 수준이라 핵심 결과 근거·29편 수에는 포함하지 않았다. 탐색 후보가 있다는 사실과 유의미한 결론 변경을 구분한다.

검색은 모든 출판사·모든 버전의 철회 상태를 보증하지 못한다. 색인 지연과 접근 실패가 남아 있다. 이번 글은 이전 판단의 정밀화이며 완전한 학계 지도나 메타분석이 아니다.
