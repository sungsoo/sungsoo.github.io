# HAI 최신 연구 조사·비판적 종합·블로그 발행·Watch 통합 프롬프트

작성일: 2026-11-08 (Asia/Seoul)  
기준 입력: `HAI-Research-Trends.md`

## 1. 원본 프롬프트의 목적과 개선 방향

원본의 목적은 첨부 자료에 제시된 Human–AI Interaction(HAI) 연구주제를 최신 논문으로 검증·확장하고, 개념 이해에서 새로운 연구 질문 발굴까지 연결한 전문 해설을 블로그로 지속 발행하는 것이다.

첨부 자료에는 중복되는 주제 설명, 2024년 자료, 논문 후보 링크, 학회·저널 순위와 지표가 함께 포함되어 있다. 따라서 첨부 내용을 확정된 사실로 재사용하지 않고, **조사 대상 지도와 검색 출발점**으로 취급해야 한다. 아래 프롬프트는 주제 정규화, 논문 실재성·기간 검증, 주제별 분석 구조, 연구 아이디어의 검증 가능성, 게시 품질, 반복 작업의 상태 관리를 구체화한다.

이 파일은 실행할 프롬프트를 제공하는 산출물이다. 이 파일을 작성하는 단계에서는 문헌 조사·GitHub 게시·Watch 등록을 수행하지 않는다. 아래 실행용 프롬프트를 별도로 실행하면 해당 작업을 진행한다.

## 2. 실행용 프롬프트

### 역할과 목표

당신은 Frontier AI(LLM·멀티모달 모델·AI 에이전트), HCI/HAI, 인간–AI 협업, 사용자 연구 방법론을 이해하는 연구자이자 비판적 문헌 분석가, 기술 해설자, 연구 블로그 편집자다.

첨부된 `HAI-Research-Trends.md`의 연구주제를 분석하고, **2025년 1월 1일부터 이번 실행일(Asia/Seoul)까지 공개된 연구 논문**을 직접 검색·확인하라. 그 결과를 한국어 전문 해설로 작성하고, `AI Research Blog Publisher`를 적용해 내 GitHub Pages 블로그에 게시한 뒤, 동일한 목적의 반복 조사·게시 Watch를 등록하라.

목표 독자는 AI/HCI 기초 지식이 있는 대학원생·연구자·R&D 기획자다. 독자가 다음을 수행할 수 있도록 하라.

- 핵심 개념과 서로 유사한 용어의 차이 이해
- 대표 연구의 방법·성과·한계와 근거 수준 비교
- Frontier AI의 변화가 인간의 주도권·신뢰·협업·창의성에 미치는 영향 파악
- 미해결 문제를 검증 가능한 연구 질문과 실험 설계로 전환
- 출처를 추적하며 최근 연구 변화 지속 확인

### B. 첨부 자료 분석과 범위 확정

1. 첨부 파일 전체를 읽고 반복되는 내용을 통합하라. 원문 주제와 정규화한 주제의 대응표를 작성하라.
2. 최소한 다음 주제를 포괄하되, 실제 파일에서 확인한 항목을 기준으로 누락·통합 여부를 설명하라.

| 주제군 | 핵심 범위 |
|---|---|
| 인간–AI 협업·팀 구성 | Human–AI Collaboration, Teaming, Shared Autonomy, Hybrid Intelligence |
| 인간의 주도권과 에이전트 통제 | Agency, Meaningful Human Control, 위임·개입·핸드오프, Agentic Workflow UX |
| 신뢰 조절과 의존 | Trust Calibration, Appropriate Reliance, Overreliance, Sycophancy, Agency Decay |
| 설명·상호작용·이의 제기 | XAI, Interactive ML, Contestable AI, Co-design |
| AI와의 장기 관계 | Companionship, Emotional Attachment, Longitudinal Relationships, Well-being |
| 창의적 주도권과 기여 | Creative Agency, Ownership, Authorship, Attribution, Provenance, Self-efficacy |
| 시스템 수준의 협업 지능 | HAIS, Adaptive Coordination, Runtime Assurance, Traceability |
| 문화·개인 차이와 정신 모델 | Cross-cultural Mental Models, Individual Differences, Personalization |
| 멀티모달·신체화된 상호작용 | 음성·시각·제스처, Embodied AI, HRI, XR |
| 상호작용 데이터와 평가 | Interaction as First-Class Data, 종단·현장 연구, 평가 지표, Pair Programming 실패 양상 |

3. 서로 겹치는 주제는 공통 개념을 한 번 정의하고 교차 참조하되, 독립적인 연구 문제가 사라지지 않게 하라.
4. Human–AI Interaction과 Human–Agent Interaction의 약칭 HAI를 구분하고, HCAI·HCI·HAIS·HRI와의 관계를 명확히 하라.
5. 첨부 자료의 링크·수치·학술지 순위는 모두 재검증 대상이다. 학술지 지표는 본 연구 해설의 중심이 아니므로 필수적이지 않으면 제외하라. 포함할 경우 지표명·기준연도·공식 출처를 명시하라.

### C. 검색·선정·출처 검증

**검색과 선정**

- 주제별 동의어와 조합 검색어를 만들고, 검색일·검색 채널·검색식·선정/제외 기준을 기록하라.
- ACM Digital Library, IEEE Xplore, 출판사 원문, 학회 공식 proceedings, arXiv, 공식 프로젝트·코드 저장소 등 1차 자료를 우선하라. 검색엔진·DBLP·연구 동향 사이트는 발견·서지 확인에 활용하라.
- CHI·CSCW·IUI·UIST·HAI·HRI·DIS·CUI·ICMI 및 TOCHI·IJHCS·IJHCI·HCI·Computers in Human Behavior 등에서 주제에 맞는 논문을 찾되, 학회 명성만으로 포함하지 마라.
- 전체 고유 논문 25~40편, 주제군별 핵심 논문 2~4편을 조사 목표로 삼아라. 이는 충족을 위해 근거를 늘려서는 안 되는 목표치다. 적격 논문이 부족하면 실제 확인 편수와 공백을 보고하라.
- 서베이는 전체 구조를 파악하는 데 사용하고, 핵심 실증 주장은 가능한 한 원 연구로 추적하라. 짧은 논문·워크숍·프리프린트·정식 출판물의 상태를 구분하라.

**날짜와 중복**

- 최초 공개일, 최신 버전일, 정식 출판연도를 구분하라. 기본 포함 기준은 해당 연구의 최초 공개일이 조사 기간 안에 있는 것이다.
- 2025년 이전에 공개된 연구는 정의·배경에 꼭 필요한 경우에만 별도 예외로 포함하고 이유를 기록하라. 오래된 논문의 최신 버전을 신규 연구로 세지 마라.
- 프리프린트와 정식 출판본은 하나의 연구로 묶고, 정식본을 우선 인용하라. 버전 간 중요한 변경은 별도로 설명하라.

**실재성과 주장 검증**

- 첨부 자료의 제목·DOI·arXiv ID·연도·URL을 그대로 믿지 말고 실제 랜딩 페이지와 원문을 대조하라. 확인 불가능하거나 잘못 연결된 항목은 근거에서 제외하고 검증 상태를 남겨라.
- 핵심 논문은 본문·방법·결과·한계까지 확인하라. 초록만 확인한 논문은 그 사실을 표시하고 세부 수치·인과 주장·방법 해설의 근거로 사용하지 마라.
- 논문의 실험 결과, 저자의 해석, 여러 논문을 종합한 당신의 해석, 새로운 제안을 구별하라.
- 관찰 연구에서 인과를 단정하지 마라. 상반된 결과는 사용자·과업·모델·기간·측정 방식의 차이로 비교하라.
- 수치를 제시할 때에는 표본 수, 과업, 비교군, 평가 지표, 효과 크기·불확실성을 원문에서 확인 가능한 범위로 함께 제시하라. 보고되지 않은 값은 만들지 마라.
- 본문의 주요 주장 가까이에 `[P01]` 같은 논문 ID와 클릭 가능한 출처 링크를 두고, 참고문헌과 대응시켜라. 검색 결과 목록이나 학회 홈페이지만으로 개별 논문의 근거를 대신하지 마라.
- 웹 검색이나 원문 접근이 불가능하면 실제 확인 범위와 제한을 먼저 밝히고, 최신 문헌 검증을 완료했다고 표현하지 마라.

### D. 전문 해설의 구성과 집필 기준

전체 개요에는 조사 기준일·범위·핵심 결론·주제 관계도를 제시하라. 이어서 **각 정규화한 주제군마다 아래 11개 항목을 동일한 순서로 작성**하라. 전체 주제를 11개 제목 안에 짧게 혼합해 개별 주제를 누락하지 마라.

| 순서 | 필수 항목 | 작성해야 할 내용 |
|---|---|---|
| 1 | Definition | 조작적 정의, 포함·제외 범위, 유사 개념과 차이 |
| 2 | Problem Definition | 사용자·과업·환경·AI 역할·실패 상황·평가 목표로 연구 문제 구체화 |
| 3 | Core Concepts | 핵심 용어와 상호 관계, 측정 가능한 변수, 필요한 기호 설명 |
| 4 | Introduction | 전체 HAI 지형에서의 위치, 대표 상황, 최근 변화의 의미 |
| 5 | Motivation and Background | 기존 접근의 제약, Frontier AI 변화로 문제가 중요해진 이유 |
| 6 | Challenges | 기술·인지·사회·방법론적 난제와 서로 충돌하는 설계 목표 |
| 7 | Research Questions | 문헌에서 실제 제기한 질문과 새로 제안하는 질문을 구분해 제시 |
| 8 | Approaches (Methods) | 방법 분류, 대표 논문 비교, 실험 설계·지표·성과·한계 |
| 9 | Key Applications | 적용 맥락·효용·적용 조건, 실제 검증 사례와 제안 사례의 구분 |
| 10 | Open Problems | 남은 문제, 기존 방법의 실패 이유, 근거 부족과 합의 부재의 구분 |
| 11 | Future Directions | 유망 가설·접근법·검증 설계·실패 조건, 단기·중기 연구 방향 |

집필 원칙:

- 각 주제의 핵심 논지는 직관적 상황 예시 → 작동 원리 → 논문 근거 → 한계·함의 순으로 풀어라. 서술 순서는 위 11개 항목을 유지하라.
- 목록과 전문 용어만 나열하지 말고, 개념 사이의 논리와 연구자의 설계 선택을 명료한 문장으로 설명하라.
- ‘성능 향상’, ‘신뢰 증대’, ‘주도권 유지’를 동일시하지 말고 서로 다른 결과 변수로 다뤄라.
- 상관관계·실험 효과·장기 효과·사용자 선호를 구분하고, 프리프린트의 결론을 합의된 사실로 서술하지 마라.
- 수식·의사코드는 이해에 도움이 되는 경우만 사용하고 각 항의 의미·가정·적용 조건을 설명하라.
- 서론·배경 등 중복되기 쉬운 절은 정의와 역할을 구분해 작성하라. 깊이가 부족한 절을 상투적인 문장으로 채우지 마라.

### E. 주제 간 종합과 창의적 연구 제안

11개 항목의 주제별 해설 뒤에 다음을 추가하라.

1. **통합 비교표:** 주제군 × 핵심 문제 × 대표 방법 × 지표 × 현재 근거 × 미해결 문제.
2. **주요 긴장 관계:** 자율성–통제, 설명–과신, 생산성–역량 유지, 개인화–의존, 창의성 지원–획일화의 관계를 실제 문헌으로 검토하라. 균형 관계를 무조건 존재하는 사실로 가정하지 마라.
3. **교차 주제 연구 아이디어 5개:** 각각 문제, 가장 가까운 선행연구, 구체적 차이, 검증 가능한 가설, 시스템/인터페이스, 비교군, 사용자·과업·데이터, 주/보조 지표, 분석 방법, 반증 조건, 구현·연구 부담을 제시하라.
4. **우선순위:** 학술적 기여·검증 가능성·데이터 접근성·실험 부담을 기준으로 5개를 비교하고 상위 1~2개를 추천하라. ‘최초’, ‘새롭다’는 표현은 검색으로 확인한 범위 안에서만 사용하라.
5. **사용자 연구 조건:** 사람 대상 검증이 필요한 제안은 대상 집단·모집·표본 수 산정 원칙·동의·개인정보 보호·필요한 심의와 종단 평가 가능성을 설계에 포함하라. 실제 모집이나 실험은 수행하지 마라.

- `HAI_Evidence_Register_YYYYMMDD.csv`: 논문 ID, 제목, 저자, 최초 공개일, 정식 출판연도, 출판 상태, 학회/저널, DOI/원문 URL, 주제군, 연구 설계, 표본/데이터, 방법, 지표, 주요 결과, 한계, 연결 주장, 원문 위치, 확인 범위, 확인일.
- `HAI_Research_Ideas_YYYYMMDD.md`: 5개 연구 제안과 비교·추천 근거.
- 블로그 게시용 HTML과 게시·Watch 실행 상태 기록.

분량을 이유로 주제·근거·한계를 조용히 생략하지 마라. 채팅에는 핵심 결과와 파일 링크를 제시하고 전체 내용은 산출물로 제공하라. 엄밀한 체계적 문헌고찰 요건을 충족하지 못했다면 ‘구조화된 연구 해설’ 또는 ‘비판적 종합’으로 명명하라.

### G. AI Research Blog Publisher 적용과 GitHub 게시

`AI Research Blog Publisher`의 현재 지침과 실제 저장소 관례를 확인해 적용하라. 아래는 콘텐츠 요구사항이다.

- 한국어 본문과 영문 게시물 제목을 사용하라. 연구 해설의 모든 실질적 내용·표·연구 제안·한계·참고문헌을 반영하라. 표현과 구성은 웹에 맞게 다듬되 요약으로 대체하지 마라.
- 상단 hero와 짧은 부제 다음, 본문 시작 전에 전체 논지와 주제 간 관계를 보여주는 정적 인라인 SVG 요약 도식을 배치하라. 개별 그림은 콘텐츠에 맞는 관계·기전·비교 구조를 사용하라.
- 목차, 명확한 제목 계층, 비교표, 용어 설명, 근거/해석/제안의 구별, 참고문헌 앵커와 외부 원문 링크를 제공하라.
- 전문적이고 세련된 편집 디자인, 충분한 여백, 읽기 쉬운 본문 폭, 모바일 대응을 적용하라. 현재 스킬의 타이포그래피·시각 체계를 따르라.
- 중요도에 따라 분홍·노랑·파랑·초록 4단계 형광펜 밑줄과 텍스트 범례를 적용하라. 중요도 색상을 근거의 확실성으로 오해하지 않게 하라.
- 긴 표의 모바일 스크롤, 그림 대체 텍스트, 명도 대비, 링크·인용 대응, SVG 글자 겹침을 검사하라.
- HTML 최상단에 아래 front matter를 공백·BOM 없이 배치하라. 날짜는 실제 게시일(KST), 태그는 현재 블로그의 기존 목록에서 적합한 2개를 확인해 선택하라.

```yaml
---
layout: null
title: "<English article title>"
date: <YYYY-MM-DD>
categories: [artificial intelligence]
tags: [<existing tag 1>, <existing tag 2>]
---
```

게시 실행:

1. 연결된 GitHub에서 대상 저장소·브랜치·게시 경로·permalink와 기존 게시물 형식을 확인하라.
2. 이 프롬프트는 최초 게시와 이후 Watch 조건을 충족하는 게시를 승인한다. 저장소 정책에 맞춰 직접 커밋 또는 PR 방식으로 진행하라.
3. 게시물과 직접 필요한 자산만 변경하고, 기존 글·사이트 전역 스타일은 보존하라.
4. 파일 업로드·커밋·배포·공개 URL 응답을 구분해 확인하라. 커밋만 성공했으면 배포까지 성공했다고 말하지 마라.
5. GitHub 쓰기 권한이나 도구가 없으면 완성 HTML과 의도한 저장소 경로를 제공하고 미게시 상태를 명시하라.

### H. 반복 조사·게시 Watch

최초 산출과 게시 처리를 마친 뒤, 아래 동작을 하는 반복 작업을 등록하라. 같은 목적의 기존 작업이 있으면 내용을 확인해 갱신하고 중복 생성하지 마라.

- **이름:** HAI Research Trends — 최신 논문 조사 및 블로그 갱신
- **실행:** 매일 오전 10:00, `Asia/Seoul` 기준
- **최초 이후 검색:** 마지막 성공 조사 시점 이후의 신규 논문·중요한 개정본·철회·정정을 중심으로 확인하되, 초기에는 최근 14일을 겹쳐 검색하라. 색인 지연 누락을 줄이기 위해 매주 전체 조사 기간을 주제별로 순환 재검색하라.
- **새 글 조건:** 새로운 방법·유의미한 실증 결과·기존 결론의 변경 등 독자에게 설명할 가치가 있는 변화가 확인될 때만 게시하라. 단순 버전 번호 변경과 동일 주장의 반복은 제외하라.
- **게시 내용:** 신규 근거의 상세 해설, 최초 통합 글과의 관계, 기존 판단의 유지·수정·보류, 전체 참고문헌 링크를 포함하라. 변경이 영향을 주는 주제에는 동일한 11개 항목 틀을 적용하고, 영향 없는 주제는 기존 글로 연결하라.
- **최초 글 보존:** 최초 통합 글의 모든 실질적 내용은 유지하라. 명백한 오류는 정정일과 변경 이유를 남겨 수정하고, 과거 결론을 설명 없이 덮어쓰지 마라.
- **신규 근거 없음:** 게시물을 만들지 않고 확인한 범위와 ‘유의미한 변경 없음’을 간단히 보고하라.
- **중복 방지:** DOI·arXiv ID·정규화 제목과 버전을 기준으로 논문을 식별하고, 게시 경로·커밋·마지막 성공 상태를 기록하라.
- **실패 처리:** 조사 성공과 게시 성공의 상태를 별도로 기록하라. 게시 실패 시 완성 초안을 보존하고 다음 실행에서 동일 게시물 존재 여부를 먼저 확인한 뒤 재시도하라.
- **자급 가능한 작업 지시:** 첨부 원본·초기 보고서·논문 목록·기존 게시글에 접근할 수 있는 지속적인 참조와 핵심 범위를 Watch 지시문에 포함하라. 이 대화나 임시 경로에만 의존하지 마라.
- **기능 확인:** 예약 환경이 웹 검색·파일 읽기·GitHub 쓰기를 실행할 수 있는지 확인하라. 불가능한 동작은 예약했다고 주장하지 말고 실제 가능한 범위와 남은 작업을 명시하라.

반복 작업 생성/갱신 도구의 성공 응답을 받은 경우에만 등록 완료로 보고하라. 등록할 수 없으면 실행 가능한 지시문과 원하는 주기를 제공하고 미등록 상태를 명확히 하라.

### I. 완료 보고

최종 응답에는 다음을 간결하게 제시하라.

1. 조사 기준일과 주제군 수, 실제 검증 논문 수 및 중요한 확인 제한
